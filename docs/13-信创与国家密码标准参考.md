## 1. 国密算法标准对照

| 算法 | 国家标准（GB/T） | 行业标准（GM/T） | 用途 | 本项目状态 |
|------|------------------|------------------|------|------------|
| SM3 杂凑 | GB/T 32905-2016 | GM/T 0004-2012 | 数据摘要、完整性 | ✅ 已实现（stdx `SM3`） |
| HMAC-SM3 | （HMAC 见 RFC 2104，以 SM3 为原语） | GM/T 0041 系列使用 SM3 派生 | 消息认证、密钥派生 PRF | ✅ 已实现（逐字节对齐 OpenSSL 3.5.7） |
| SM4 分组密码 | GB/T 32907-2016 | GM/T 0002-2012 | 对称加密 | ✅ 已实现（CBC / CTR 模式） |
| PBKDF2-HMAC-SM3 | （RFC 2898，PRF=HMAC-SM3） | — | 口令派生密钥 | ✅ 已实现（自研，原语用 HMAC-SM3） |
| SM2 椭圆曲线公钥 | GB/T 32918-2016（1~5） | GM/T 0003-2012 | 数字签名 / 公钥加密 / 密钥交换 | ❌ 未实现（SDK 未提供） |
| SM4-GCM 认证加密 | —（GCM 属 NIST SP 800-38D，非国密模式） | — | 认证加密 | ❌ 不可用（stdx 报 `create tag error`） |

> ⚠️ **关于 SM4-GCM 的澄清**：GCM 是 NIST 模式，并非国密标准的一部分。
> 设计文档 `docs/01~07` 中出现的「SM4-GCM」是**目标表述**，真实落地为
> SM4-CBC/CTR + HMAC-SM3（Encrypt-then-MAC，EtM）。从国密合规角度，
> 「SM4 + HMAC-SM3」比「SM4-GCM」更贴合现有 stdx 能力与国密推荐实践，
> 故当前方案在合规性与可行性上更优。详见 `docs/08`。

## 2. 已实现能力（含实测依据）

来源：`packages/ams-crypto/src/impl/impl.cj` 文件头注释（逐版本复测记录）。

| 能力 | 实现位置 | 实测结论 |
|------|----------|----------|
| SM3 摘要 | `impl.cj` `SM3()` | 与国标标准值一致 |
| HMAC-SM3 | `impl.cj` `hmacSm3()` | 与 OpenSSL 3.5.7 逐字节一致 |
| SM4-CBC | `impl.cj` `SM4(OperationMode.CBC, ...)` | 与 OpenSSL 3.5.7 逐字节一致 |
| SM4-CTR | `impl.cj` `SM4(OperationMode.CTR, ...)` | 流模式可用 |
| PBKDF2-HMAC-SM3 | `impl/pbkdf2.cj` | 与 Python `hashlib.pbkdf2_hmac('sm3', ...)` 对齐 |
| 盲索引 | `blindindex.cj` | 归一化值 + 派生密钥的 HMAC-SM3（32 字节） |

**密码学设计原则（强制）**：
- 对称加密一律 **Encrypt-then-MAC**：先 SM4 加密，再对整个密文算 HMAC-SM3，
  解密前先验 MAC（防篡改、防选明文）。
- 缺密钥 / 缺加密提供者必须 **失败关闭**（抛错），绝不降级成弱 token 或空摘要。
- 密钥加密密钥（KEK）派生盲索引与附件 DEK 包裹密钥，写读两侧一致（FR-SRC-005）。

| 项 | 现状 | 影响与缓解 |
|----|------|------------|
| SM2 公钥密码 | SDK（stdx 1.0.5.1 / 1.2.0.1）未提供 | 导出包**签名**改用 **HMAC-SM3（对称）** 而非公钥签名；无非对称密钥体系，暂不支持第三方公钥验签 |

## 4. 合规边界声明

1. **算法对齐 ≠ 产品认证**：AMS 在算法层面使用 SM3 / SM4 / HMAC-SM3，
   属于「技术对齐国密」，但**尚未**取得国家密码管理局的商用密码产品型号认证。
   涉及政务 / 金融等强监管场景，需走正式测评与认证流程。
2. **实现来源**：当前依赖 `stdx` 提供的 SM3/SM4/HMAC 原语。其底层是否通过
   国密合规性测试，需向 SDK 提供方（仓颉 / 华为）索取合规声明；本仓库不背书
   其认证状态。
3. **降级策略**：任何密码学原语缺失时，系统按「失败关闭」而非降级，
   保证不会在弱安全状态下运行。

## 6. 对外对接建议（API 接入方）

- 对外 API（见 `docs/14-对外API规范-OpenAPI.yaml`）统一走 **Bearer Token**，
  令牌由 `/api/auth/login` 下发；生产必须配置 `AMS_TOKEN_SECRET`（≥32 字节）。
- 导出包完整性：当前以 HMAC-SM3 做防篡改签名（对称），接入方需共享同一
  `AMS_KEK` 派生密钥才能验签；后续若切换到 SM2，可支持非对称验签与密钥轮换。
- 不建议接入方依赖任何「被降级」的能力；涉及强合规场景请以正式测评结论为准。
