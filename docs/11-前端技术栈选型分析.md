## 0. 结论先行（TL;DR）

| 维度 | 推荐方案 | 是否满足三项约束 |
| --- | --- | --- |
| 框架 | **Vue 3 + TypeScript**（组合式 API） | ✅ 无 JVM；XSS 默认转义；信创生态最全 |
| 构建 | **Vite + esbuild/Rollup**（Node.js 开发工具） | ✅ 全程无 JVM 参与 |
| 状态/路由 | **Pinia + Vue Router** | ✅ 纯 JS；路由降级 hash 模式适配国产浏览器 |
| 组件库 | **Element Plus / Ant Design Vue**（均信创认证） | ✅ 国产浏览器适配已验证 |
| 国密 JS | **sm-crypto**（SM2/SM3/SM4，纯 JS 无 WASM 依赖） | ✅ 即便 WebAssembly 被禁用仍可用 |
| 测试 | **Vitest + Playwright** | ✅ 无 JVM |
| 部署 | 静态资源由 **ams-server 同源托管**（ADR-008） | ✅ 不引入 Nginx/JVM 旁路 |

> 本文与既有 **ADR-002（前端 Vue 3 + TS + Vite）完全一致**，是对其的**安全与信创落地补强**，不推翻原决议。React 作为备选保留；Svelte 作为"高安全可选"用于敏感模块。

## 1. 三项硬约束的验收标准

| 约束 | 在本项目语境下的验收标准 | 映射的安全设计 |
| --- | --- | --- |
| **安全性强** | 默认阻断 XSS/存储型脚本；CSP 无 `unsafe-inline`；CSRF 双提交令牌；令牌与敏感态不进 `localStorage`；依赖锁版本 + SBOM + 产物 SM2 验签 | 威胁 T-05(XSS)、T-06(CSRF)、T-21(供应链)、T-22(产物篡改)、S-7(国密) |
| **不使用 JVM** | 构建期与运行期均无任何 JVM 进程：构建走 Vite/Node，运行是纯静态 JS；不引入 GWT/Vaadin/JSF/Play-Java 等 JVM 系方案 | 与后端 Cangjie（无 JVM）、openGauss 驱动"拒绝 JDBC+JVM"（见架构 §6.1）保持一致 |
| **国产化适配强** | 可在统信 UOS / 麒麟 / 中科方德 + 龙芯 LoongArch / 鲲鹏 / 飞腾 / 兆芯 / 海光 上运行；兼容奇安信/360/龙芯/红莲花/赢达信等国产浏览器；国密通信/解密链路打通；等保三级可举证 | 等保 2.0 三级、GM/T 0054 国密应用、前端渲染解耦（标准 Web 技术栈） |

## 2. 框架选型对比（安全 × 无 JVM × 信创）

| 框架 | XSS 默认转义 | 逃生舱（危险 API） | CSRF 内建 | 构建工具（无 JVM） | 信创生态 | 供应链攻击面 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **Vue 3** | ✅ 模板 `{{ }}` 自动转义 | `v-html`（需配合 DOMPurify） | ❌ 需 axios 拦截器/双提交 | Vite/esbuild（Rust/JS） | **最强**：Element Plus、Ant Design Vue 均信创认证；ECharts 完美 | 较小 | ✅ **主推** |
| **React 18** | ✅ JSX 自动转义 | `dangerouslySetInnerHTML` | ❌ 需生态库 | Vite/webpack（JS） | 强，但信创组件适配略少 | 中 | 备选 |
| **Svelte 5** | ✅ 模板转义 | `{@html}` | ❌ 需库 | Vite（JS） | 较弱，长期维护风险 | **最小**（编译为原生 JS，框架运行时极小） | 高安全可选模块 |
| **Solid** | ✅ 模板转义 | `innerHTML` | ❌ 需库 | Vite（JS） | 弱 | 小 | 不选 |
| **原生 JS** | ❌ 手动转义 | 任意 DOM API | ❌ 需库 | 无框架构建 | — | 最小但开发成本高 | 不选（除非极简页） |

**关键判断**：
- 三者在「无 JVM」「XSS 默认转义」上等价；差异在**信创生态成熟度**与**供应链面**。
- **Vue 3 综合最优**：中文文档/社区最充足，信创认证组件最多，团队上手成本最低（架构 §2.3 已论证）。
- **Svelte 价值点**：编译产物是接近原生 JS、框架运行时极小 → 供应链攻击面最小。可用于「审计日志查看器」「口令策略配置」等高危但交互简单的模块，作为纵深防御的补充，而非全局替换。

## 3. 构建与运行时（无 JVM 证明）

**构建链路（全程无 JVM）**：
```
源码(.vue/.ts) → Vite(esbuild 预构建 + Rollup 打包) → 静态产物(dist/)
                                                     → 由 ams-server 同源托管(ADR-008)
```
- Vite 基于 esbuild（Go 实现）/ Rollup（JS）；Node.js 仅作**开发期工具链**，不参与运行时。
- **产物是纯静态 HTML/JS/CSS**：浏览器直接执行，运行期无 JVM、无 Node、无额外常驻进程。
- 与后端一致：Cangjie 编译为原生可执行文件（无 JVM）；openGauss 驱动明确拒绝 JDBC+JVM 旁路（架构 §6.1）。**整个产品栈 JVM-free**。

**明确排除（满足"不使用 JVM"的红线）**：
| 方案 | 排除原因 |
| --- | --- |
| GWT（Java→JS） | 编译依赖 JVM 工具链 |
| Vaadin / JSF | 服务端 UI 渲染依赖 JVM |
| Play Framework (Java) | JVM 运行时 |
| Scala.js / Kotlin/JS | 虽编译为 JS，但编译工具链本身跑在 JVM 上，违反"不使用 JVM"的构建期要求 |
| 前端用 Maven/Gradle frontend 插件拉起 webpack | 构建编排依赖 JVM |

**Node.js 的信创可用性**：龙芯/鲲鹏/飞腾平台均有 Node.js 二进制（社区与发行版仓库提供）；构建与依赖安装走**私有 npm 源**（禁止境外 CDN，见 §4.7）。

## 4. 安全设计落地

### 4.1 XSS（威胁 T-05）
- 模板插值默认转义（Vue `{{ }}`）→ 阻断基础存储型 XSS。
- **全局禁令**：`v-html` / `dangerouslySetInnerHTML` 等价写法。CI 静态检查（ESLint + `eslint-plugin-security`）拦截。
- 富文本字段（如备注）走**白名单净化器**（DOMPurify，配置为仅允许安全标签），且服务端再次净化（纵深防御）。
- 安全专章 §8.3 已要求 CSP + 输入净化；前端负责"输出转义 + 禁用逃生舱"，后端负责"CSP 头 + 净化"。

### 4.2 CSP（严格模式，无 `unsafe-inline`）
- 采用 **nonce 方案**：由 `ams-server` 在响应 `index.html` 时生成一次性 nonce，同时下发 `Content-Security-Policy: script-src 'self' 'nonce-<val>'`。
- 因前端由后端同源托管（ADR-008），nonce 注入点天然在服务端，无需前端构建期写死。
- 禁止 `unsafe-inline`、`unsafe-eval`；`style-src` 用 nonce 或 hash；`frame-ancestors 'none'`（防点击劫持，呼应 §8.3）。

### 4.3 CSRF（威胁 T-06）
- Cookie 属性：`HttpOnly; Secure; SameSite=Strict`（后端已定，安全专章 §4.2）。
- 写操作强制**双提交 Token**：`axios` 拦截器从 `meta` 或内存读取 CSRF token，随 `X-CSRF-Token` 头发送；后端中间件校验（架构 §3.3 步骤⑤）。
- 同源托管已缩小 CSRF 面，但分享链接/跨站图片等仍存在，故保留双提交作为兜底。

### 4.4 令牌与敏感态存储（呼应安全专章 §4.2、§5.2）
- **访问令牌存内存**（SPA 不落 `localStorage`，避免 XSS 可读）。
- **刷新令牌用 HttpOnly + Secure + SameSite=Strict Cookie**（后端签发，前端不可读）。
- 仅非敏感 UI 偏好（主题、语言）可入 `localStorage`；**任何凭据/权限摘要/审计敏感数据不进 localStorage**。

### 4.5 路由模式（信创浏览器适配关键）
- **默认 SPA history 模式**，但对**国产浏览器降级为 hash 模式**：部分奇安信/360 信创版内核在 history 回退、深链刷新时存在兼容问题（信创改造经验，见 §5.2）。
- 通过**特性探测**（非 UA 识别）决定路由模式，避免 UA 伪造导致的误判。

### 4.6 第三方组件替换清单（信创兼容）
| 用途 | 推荐（信创友好） | 备注 |
| --- | --- | --- |
| UI 组件 | Element Plus / Ant Design Vue | 均通过信创认证 |
| 图表 | ECharts | 完美支持信创浏览器 |
| 表格 | vxe-table / handsontable 国产版 | — |
| 富文本 | wangeditor / tinymce 信创版 | — |
| 文档预览 | OFD 预览插件（国产，替换 PDF.js 的 OFD 场景） | 国产公文常用 OFD |

### 4.7 供应链安全（威胁 T-21 / T-22）
- **锁版本**：`package-lock.json` / `pnpm-lock.yaml` 提交并 `npm ci` 安装，禁止浮动版本。
- **私有源**：依赖安装走内网/私有 npm 源，**禁止境外公共 CDN**（呼应信创改造要求）。
- **SBOM**：CI 生成前端 SBOM（CycloneDX），与后端 SBOM 合并归档。
- **漏洞扫描**：`npm audit` / OSV 数据库门禁（0 高危/严重）。
- **产物签名**：前端构建产物随整体包由 ams-server 用 **SM2 签名**（`SIGNATURE.sig`，见架构 §7.3、§9 安全运营），部署前验签。

## 5. 国产化适配落地清单

### 5.1 操作系统与 CPU
- 纯 Web 标准技术栈（HTML5/CSS3/ES2020），**不依赖浏览器专有 API**（呼应元序平台前端渲染解耦经验）。
- 目标环境：统信 UOS、中标/银河麒麟、中科方德 × 龙芯 LoongArch、鲲鹏/飞腾(ARM)、兆芯/海光(x86)。前端无需按平台分支。

### 5.2 国产浏览器适配（三件事）
1. **特性探测替代 UA**：用 `typeof`/`CSS.supports`/`document.queryCommandSupported` 探测能力，绝不靠 UA 字符串判断（UA 可伪造且碎片化）。
2. **WebAssembly 可用性探测**：本项目国密用**纯 JS 的 sm-crypto（无 WASM 依赖）**，即使浏览器禁用 WASM 仍可用；若后续引入 WASM 加速，需先探测再降级到 JS 实现。
3. **字体与打印**：指定开源字体（文泉驿微米黑 / 思源黑体），避免黑体/宋体在非 Windows 环境缺失；打印与 OFD 预览走国产浏览器适配逻辑。

> 实测依据：奇安信可信浏览器（Chromium 内核）**明确兼容 vue/react/angular/echarts/bootstrap**，支持 WebGL/WebAssembly/国密通信，覆盖龙芯/兆芯/飞腾/海光全 CPU 平台；龙芯浏览器（Gecko+Blink 双核）支持 SM2/SM3/SM4。Vue 3 路线在这些环境已获厂商背书。

### 5.3 国密端到端
| 环节 | 责任方 | 前端动作 |
| --- | --- | --- |
| 传输（国密 TLS / GMTLS） | 接入层 + 国产浏览器 | 浏览器内置国密根证书，自动识别国密站点；前端无代码改动，仅须由后端/网关启用双证书体系 |
| 导出包解密（SM4） | **前端** | 用户用口令派生密钥，前端 `sm-crypto` 解密导出包（安全专章 §6.5.3） |
| 导出包验签（SM2） | **前端** | 校验 `signature.sig`，失败拒绝导入（TC-SEC-50） |
| 字段加密/盲索引 | 后端 | 前端不接触密钥，仅渲染脱敏/掩码值 |

**国密 JS 库选型**：
- **sm-crypto（主推）**：最流行，~30KB gzipped，纯 JS，**浏览器+Node 均支持**，SM2/SM3/SM4 齐全 → 契合"WASM 可能被禁用"的信创约束。
- gm-crypto（备选）：API 更优，但浏览器支持度标称存疑，作为性能备选。
- **强制**：从官方 npm 源安装并**锁定版本**，禁止运行时动态拉取。

### 5.4 等保三级映射（前端可举证部分）
| 等保条款 | 前端落地 |
| --- | --- |
| 8.1.4.1 身份鉴别 | 双因素 UI、强口令策略提示、登录失败锁定反馈 |
| 8.1.4.2 访问控制 | 基于 RBAC 的按钮/路由级权限（权限点来自后端令牌） |
| 8.1.4.3 安全审计 | 审计日志只读展示 + 链校验状态徽标（verifyChainFrom 结果） |
| 8.1.4.6/7 完整性/保密性 | CSP + HTTPS + 敏感字段不落 localStorage |
| 8.1.4.8 数据备份恢复 | 导出包 SM2 验签防篡改 |

## 6. 与现有 Cangjie 后端的对接

| 对接点 | 方式 |
| --- | --- |
| 资源托管 | ams-server 同源托管 `web/dist`（ADR-008）→ Cookie 同源，天然规避跨域，简化 CSRF |
| API 契约 | REST + JSON；统一错误码（不回显 SQL/堆栈，安全专章 §7.4） |
| 认证 | access token 内存持有；refresh 用 HttpOnly Cookie；CSRF 双提交 |
| 审计链展示 | 后端 `verifyChainFrom(records, anchor)` 已实现对子段校验（见 P0 文档对账 §7.6）；前端展示「链完整/断裂@seq」状态徽标，**前端不重新计算哈希**，只消费后端校验结论 |
| 国密导出 | 前端 `sm-crypto` 解密 SM4 + 验 SM2 签名，解密需二次确认令牌（§6.5.2 L2） |
| 安全头 | ams-server 中间件统一下发 CSP/HSTS/X-Frame-Options/Referrer-Policy（架构 §3.3 步骤③） |

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 国产浏览器内核老旧 / 特性不全 | 渲染或 API 异常 | 特性探测 + 功能降级 + hash 路由；核心交互不依赖新特性 |
| WebAssembly 被禁用 | 依赖 WASM 的库失效 | 只用纯 JS 国密库（sm-crypto），WASM 仅作可选加速 |
| 私有 npm 源不可达 / 境外 CDN 被封 | 构建失败 | 离线 vendor 依赖 + 私有源镜像 |
| 依赖投毒 | 供应链后门 | 锁版本 + SBOM + OSV 扫描 + SM2 产物验签 |
| 前端人才/生态波动 | 维护风险 | Vue 3 中文生态最成熟，文档充足 |

## 10. 与 ADR-002 的关系

- **确认 ADR-002（前端 Vue 3 + TS + Vite）有效**，本文为其安全与信创维度的补强，不修改原决议。
- 新增可沉淀为 ADR 补遗的点：
  - 国密前端库锁定 **sm-crypto**（纯 JS，无 WASM 依赖）；
  - 路由在国产浏览器**降级 hash 模式**（特性探测驱动）；
  - 前端构建产物纳入整体 **SM2 签名 + SBOM** 链路。
