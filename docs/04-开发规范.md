### 1.2.1 [必读] 仓颉 1.2.0 语法与工程约束（全部经实测踩坑确认）

> 这一节是**踩坑沉淀**，每一条都对应一次真实的编译失败。**写仓颉代码前请先读一遍。**

#### A. 语法硬约束（违反即编译失败）

| 约束 | 错误信息 | 正确写法 |
| --- | --- | --- |
| **`match` 的每个分支只能是单个表达式**，不能写 `{ 多行语句 }` | `expected '=>' in lambda expression, found 'let'` | ① 单表达式：`case X => expr`；② 多语句：抽成私有方法，分支写 `case X => this.helper(...)` |
| **同一目录下只能有一个包声明** | `found more than one package declaration` | 子包必须独立目录：`src/` 是父包、`src/error/` 是子包 |
| **类内不能用 `static` 修饰符** | `unexpected modifier 'static' on function declaration` | 静态逻辑写成「伴生对象」或放进独立的工具类 |
| **元组模式（`case (a, b) =>`）不支持** | `1-element tuple pattern is not allowed` | 改为嵌套 `match` |
| **`Array` 不可变，且无 `append` / `+`** | `invalid binary operator '+' on type 'Array<...>'` | 用 `std.collection.ArrayList`（有 `add`），最后 `toArray()` |
| **数组字面量直接用 `[...]`**，不要 `Array<T>([...])` | `missing argument for parameter list '(Int64, (Int64) -> Generics-T)'` | `["a", "b"]`；`Array<T>()` 需带参数 `Array<T>(0, repeat: "")` |
| **`@Assert` 对 enum 参数无法推断泛型** | `unable to infer generic argument of this function` | 枚举比较用 `match` 判定为 Bool 后再断言 |
| **默认参数用 `name!: Type = value`** | `expected ',' or ')', found '='` | `init(x!: Int64 = 0)` |
| **字符串方法名是 `toAsciiUpper` / `toAsciiLower` / `trimAscii`** | `is not a member of struct 'String'` | 无 `Case` 后缀 |
| **`String` 没有 `Int64.parse`** | `undeclared identifier 'parse'` | 自行实现十进制解析（本仓库 `PasswordHasher.parseInt64`） |
| **`s[i]` 返回 UInt8 字符码**，不是字符 | 字符串被拼成 `116101115...` | 取字符用 `s[i..(i+1)]`；数值运算显式 `Int64(c)` |
| **`Duration` 没有公开构造器**（只有 `Duration.Zero`） | `no matching constructor for call 'Duration'` | 用「`DateTime` 之差」或「`MonoTime` 之差」得到 Duration |
| **`StringBuilder.append` 返回 Unit，不能链式调用** | `undeclared identifier 'append'` | 逐条调用；且 `StringBuilder` 需声明为 `var` |
| **源文件里不要用 emoji** | `warning: unsecure character` | 注释用 ASCII |
| **`init` 是保留字** | `expected declaration, found keyword 'return'` | 静态初始化方法改名（如 `setup`） |
| **字符串遍历必须用 `runes()`**，不能按 `s[i]` | `IllegalArgumentException: Invalid utf8 byte sequence` | `s[i]` 是**字节**下标，中文是 UTF-8 多字节；按字节切分得到非法序列 |
| **Rune 无转码点整数的方法** | `undeclared identifier 'toUInt32'` | 用 `r.toString()` 拿字符做字面量比较 |
| **`DateTime.now().toUnixTimeStamp()` 是本地纪元** | 时间戳偏一个时区差（东八区差 8 小时） | 见下方「时间戳三连坑」 |
| **enum 不支持 `==` 运算符** | `invalid binary operator '==' on type 'Enum-XXX'` | 用 `match` 判定后比较，或写辅助函数 `eqX(a, b): Bool` |
| **`Bool` 是关键字**，作枚举成员/标识符需转义 | `expected a enum value name after '|' ... found keyword 'Bool'` | 写成 `` `Bool` ``（反引号转义），所有引用处同样要转义 |
| **`type` 是关键字**，不能作参数名 | `unclosed delimiter '('` | 改名（如 `ftype`） |
| **枚举构造器不支持带名参数** | `unclosed delimiter '('` | 改为无参枚举 + 单独的取值方法 |
| **`for ((k, v)) in arr` 元组解构不支持** | `expected 'in' in for-in expression` | 用索引遍历 `for (i in 0..arr.size)` + `let (k, v) = arr[i]` |
| **`arr[i].0` 不可访问元组成员** | `expected ';' or '<NL>', found literal '.0'` | 用解构赋值 `let (k, v) = arr[i]` |
| **`Array` 无 `sort()` 方法** | `'sort' is not a member of struct 'Array<...>'` | `import std.sort.*` 后用顶层 `sort(arr)` |
| **带默认值的参数必须用 `name!:`** | `expected ',' or ')', found '='` | `init(x!: Int64 = 0)`；**且调用时该参数需按名传** |
| **`Option` 不参与算术** | `invalid binary operator '+' on type 'Enum-Option<Int64>'` | 先 `match` 解包出值再运算 |
| **`String.indexOf` 返回 `Option<Int64>`** | 同上 | 用自定义的 `indexOf` 返回 -1 的版本，或先解包 |

#### A2. 时间戳三连坑（实测，直接影响日志与审计正确性）

```cangjie
// 错：得到的是「本地时间」对应的纪元毫秒，比 UTC 纪元偏一个时区差
let ms = DateTime.now().toUnixTimeStamp().toMilliseconds()   // 东八区偏 8 小时

// 对：取「墙上时间 + 时区」重新 parse，再取纪元毫秒
let s = DateTime.now().toString()          // 2026-10-25T13:43:05.5528085+08:00
let wall = s[0..23]                        // 2026-10-25T13:43:05.552  ← 必须含毫秒！
let ms = DateTime.parse("${wall}${timeZoneOf(s)}")
             .toUnixTimeStamp().toMilliseconds()
```

| 坑 | 说明 |
| --- | --- |
| ① 时区偏移 | `toUnixTimeStamp()` 不是 UTC 纪元。**审计日志、令牌过期时间全部依赖它**，错了会导致审计时间线错乱、令牌提前/延后失效 |
| ② 毫秒精度 | `s[0..19]` 只到秒，`s[0..23]` 才含毫秒。只取到秒会让两次取值差为 0，**毫秒级计时断言必然失败** |
| ③ 时区提取 | `DateTime.toString()` 形如 `...+08:00`，时区部分从第 11 个字符后第一个 `+`/`-` 开始；用 `DateTime.parse` 解析带偏移的字符串即得该时刻 |

> 本仓库实现见 `ams-kernel/src/time/time.cj`（`Times.nowMillis` / `Times.timeZoneOf`）与
> `ams-kernel/src/log/log.cj`（`Log.isoNow`）。两处刻意各自实现而不互相 import ——
> 同包兄弟子包之间 import 有限制，**小函数重复优于引入耦合**。

#### B. 标准库 API 缺口（实测结论）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| `std.crypto.digest` / `std.crypto.cipher` | 仅**接口** | 无 SM3/SM4 实现 |
| `stdx.crypto.digest.SM3` | ✅ | 与国标标准值一致 |
| `stdx.crypto.digest.HMAC` | ✅ | `HMAC(key, HashType.SM3)`；与 OpenSSL 3.5.7 逐字节一致 |
| `stdx.crypto.crypto.SM4` | ✅ | CBC/CTR 可用；**GCM 不可用**（报 `create tag error`，而 OpenSSL 本身支持 SM4-GCM） |
| `stdx.crypto.crypto.SecureRandom` | ✅ | CSPRNG |
| **PBKDF2** | ❌ 无此 API | 本仓库自行实现（`ams-crypto/src/impl/pbkdf2.cj`），已与 `hashlib.pbkdf2_hmac('sm3',...)` 对照 |
| `stdx.net.http` | ✅ | HTTP 服务端可用 |
| `stdx.log` | ⚠️ | **默认不向 stdout 输出**（需额外配置 LogWriter）；本仓库 `ams-kernel/src/log` 自实现 JSON Lines 输出 |

> **结论**：字段加密采用 **SM4-CBC + HMAC-SM3（Encrypt-then-MAC）**，而非 SM4-GCM。密钥包裹格式见 `ams-crypto/src/key/key.cj`。

#### C. 工程结构约束（影响构建脚本）

| 约束 | 说明 |
| --- | --- |
| **测试代码必须与产品代码物理分离** | 测试放 `packages/<pkg>/tests/<sub>/`，产品代码在 `packages/<pkg>/src/<sub>/`。**原因**：编译器优先使用 import-path 里的 `.cjo` 而非源码，若测试与产品同目录，`.cjo` 会混入未展开的测试宏，后续编译报出莫名的 `expected '=>' in lambda expression` |
| **子包的 `.cjo` 需单独编译该子包目录才产出** | `cjc -p <子包目录> --output-type staticlib --output-dir <build>` |
| **子包之间不能互相 import**（独立编译时） | 跨包依赖需按拓扑顺序编译，前置包的 `.cjo` 必须已存在 |
| **`.cjo` 优先于源码** | 源码改动后需重新构建对应包，否则编译到旧代码 |

#### D. Git Bash + Windows 的路径转换陷阱（本地构建专用）

| 陷阱 | 现象 | 规避 |
| --- | --- | --- |
| `export PATH=E:/x` 被 MSYS 转换 | 变成 `/e/x`（Windows exe 不认） | `envsetup.sh` 里 source SDK 脚本**前**先算好 Windows 风格路径并重建 PATH |
| cjc 的 `-L <path>` 选项被转换 | 变成 `-L/lib`（丢盘符），lld 找不到库 | `-L` 放进 `--link-options` 里（该参数不参与转换），且用 **Windows 风格** |
| 静态库路径用 MSYS 风格 | `could not open '/e/.../libams.app.a'` | 链接时用 **Windows 风格绝对路径** |
| 含点号的库名 | `-lstdx.encoding.hex` 定位不到 | 用 `-l:libstdx.encoding.hex.dll`（完整文件名） |
| 新加进 PATH 的工具 `command -v` 报 NOT FOUND | 实际可用 | bash **命令哈希缓存**问题，执行 `hash -r` |
| `cygpath` 转换反斜杠路径 | `E:/Cangjie` → `E://Cangjie` | 用 `cygpath -m`（`/e/x` 与 `E:/x` 都能正确转换） |
| 循环内反复 `cp` 30+ 个 dll | 累积开销明显，测试跑到一半超时 | 拷贝提到循环外，只做一次 |

> **CI 提示**：以上都是 **Windows + Git Bash 本地环境**的特有问题。CI 用标准 Linux 路径 + `cjpm`，不受影响。

#### stdx 接入方式（实测确定，照抄即可）

**① `cjpm.toml` 必须声明 bin-dependencies**（`CANGJIE_STDX` 环境变量本身 SDK 并不读取）：

```toml
[package]
  name = "ams-server"
  version = "0.1.0"
  cjc-version = "1.0.5"
  output-type = "executable"

[target.x86_64-w64-mingw32]                    # 与 `cjc --version` 的 Target 一致
  [target.x86_64-w64-mingw32.bin-dependencies]
    path-option = ["E:/CangjieLibs/windows_x86_64_cjnative/dynamic/stdx"]
```

> Linux 侧改为 `[target.x86_64-linux-gnu]` + `path-option = ["/opt/cangjie-stdlib/linux_x86_64_cjnative/dynamic/stdx"]`，ARM 侧同理。

**② 国密调用（实测可编译运行）**：

```cangjie
// ⚠️ digest 泛型函数需要同时 import 两个包：
//    stdx.crypto.digest 提供 SM3 类型，std.crypto.digest 提供 digest 函数
import stdx.crypto.digest.*
import std.crypto.digest.*
import stdx.encoding.hex.*

func sm3Hex(data: Array<Byte>): String {
    // ⚠️ digest 是「双参数」：digest<SM3>(SM3(), data)
    // ⚠️ Array<Byte> 没有 toHexString()，要用 stdx.encoding.hex 的 toHexString
    return toHexString(digest<SM3>(SM3(), data))
}
```

**③ 运行时依赖**：exe 同目录需能找到 `libstdx.*.dll` 与 `libcangjie-runtime.dll`。部署时把 `dynamic/stdx/*.dll` 与 SDK 的 `runtime/lib/<platform>/*.dll` 一并拷入（见架构 §7.4 交付物结构）。

#### F. 仓颉 1.2.0（STS）新增/变更的约束

> SDK 从 1.0.5 LTS 升级到 1.2.0 STS 后新增的坑，均经实测确认。

| 约束 | 错误信息 | 正确写法 |
| --- | --- | --- |
| **`match` 分支不支持 `if` 守卫** | `expected '=>' in case, found keyword 'if'` | 在分支体内判断：`case Some(v) => { if (cond) {...} else {...} }` |
| **具名默认参数必须按名传** | `missing argument prefix 'message:'` | `unauthorized(message: "...")`（不能写 `unauthorized("...")`） |
| **带默认值的参数需 `name!:`** | `expected ',' or ')', found '='` | `field!: String = ""` |
| **`Map` 是接口，不能实例化** | `interface 'Map' can not be instantiated` | 用 `HashMap<String, String>()` |
| **`HashMap[k]` 键不存在时抛异常** | `NoneValueException: Value does not exist!` | 用 `get(k)`（返回 Option），不要用 `[]` |
| **`Map.size` 是属性** | `no matching function for operator '()' function call` | `params.size`（无括号） |
| **`String` 无 `trim()`** | `'trim' is not a member of struct 'String'` | `s.trimStart().trimEnd()` |
| **`String` 无 `format()`** | `'format' is not a member of struct 'String'` | 手写十六进制转换 |
| **`String[i]` 是字节下标** | `invalid binary operator '==' on type 'UInt8' and 'Struct-String'` | 用 `indexOf(sub)` 定位（返回 Option） |
| **`Rune` 取码点** | `undeclared identifier 'toUInt32'` | `UInt32(ch)` |
| **`String.join` 需 Array + 具名参数** | `expected 'Struct-Array<String>', found 'Class-Iterator<String>'` | `String.join(arr, delimiter: "/")` |
| **块注释内不能出现 `/*`** | `unterminated block comment` | 改写措辞（如用「斜杠星号」） |
| **同名方法不支持重载** | 编译期签名冲突 | 用泛型 `func f<T>(...)` 区分 |
| **`e as AppError` 返回 Option** | `'code' is not a member of enum 'Option<AppError>'` | `match (e as AppError) { case Some(ae) => ... }` |
| **环境变量读取是 `getVariable`** | `undeclared identifier 'getEnv'` | `import std.env.*` 后用 `getVariable("KEY")` |
| **循环 `for (i in 0..n)` 是左闭右开** | — | `0..n` 取 n 个（0..n-1），与直觉一致 |

#### G. stdx 1.2.0 的破坏性变更（影响驱动与日志）

| 变更 | 影响 | 本项目处置 |
| --- | --- | --- |
| 全局 `logger` 变量移除，改为 `getGlobalLogger()` / `setGlobalLogger()` | 依赖旧全局变量的代码编译失败 | **ams-kernel 自实现日志**（不依赖 stdx.log），无影响；opengauss-driver 打了本地补丁（`scripts/patch-driver.py`） |
| `Logger` 接口方法集改为 `log(level, message, attrs)` | 旧的 `SimpleLogger` 实现签名不兼容 | 同上 |
| `HashMap` / `Array` / `ArrayList` **不再实现** `Serializable` | `field<Collection>(...)` 运行期抛 `extensionData is nullptr` | 驱动改用 `field<String>(name, coll.toString())`（同上游 error_response.cj 的既有做法） |
| `stdx.net.http` 的 distributor **只做精确路径匹配** | 参数化路由（`:param`）全部 404；同路径多方法抛 `already registered` | 本项目实现 `ams.api.server.ParamDistributor`（实现 stdx 的 `HttpRequestDistributor` 接口），经 `builder.distributor(d)` 注入 |

**本机两个已知坑**（实测）：

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| **cjpm 崩溃** | `cjpm build` 触发堆损坏（`0xC0000374` / `-1073741819`），**与路径、SDK 版本、工程结构、工程内容均无关**（已逐一排除）。`cjpm init` 能跑通，崩在编译阶段。**`cjc` 在任何情况下都正常** | 🔴 **本机统一用 `cjc` 直接编译验证代码**（`cjc src/main.cj -o out.exe`），`cjpm` 仅用于 CI / 其他环境。这是 cjpm 1.0.5 的 Windows 兼容性问题 |
| **Git Bash 路径风格** | `export PATH=E:/Cangjie/bin` 会被 MSYS 自动转成 `/e/Cangjie/bin`；且新加进 PATH 的工具因 **bash 哈希缓存**导致 `command -v cjc` 报 NOT FOUND（实际可用） | `envsetup.sh` 在 source SDK 脚本**前**算好 Windows 风格路径并重建 PATH；新 shell 里执行 `hash -r` |
| **stdx 传递依赖多** | 只链接单个 stdx 库会报 `undefined symbol`（如 `stdx.log:LogValue.ti`） | 链接时**全量列出** stdx 动态库；运行时把 DLL 放 exe 同目录最稳妥 |

> **给新人的提醒**：
> ① `cjpm` 在本机不可用是**已知且已归因**的，不要花时间排查路径 —— 用 `cjc` 即可。
> ② **看到 exit code 0 不等于构建成功**，一定要检查产物是否真的生成。
> ③ `command -v` 报 NOT FOUND 但直接调用却正常时，先 `hash -r` 再下结论。

## 4. 仓颉后端编码规范

### 4.1 分层职责与依赖

```
handler（HTTP 适配）→ service（用例编排）→ domain（领域规则）→ repo（数据访问）
                                                       ↘ port（接口定义）
```

| 层 | 可以做 | 不可以做 |
| --- | --- | --- |
| `handler` | 解析请求、校验入参、调用 service、组装响应 | 写业务规则、直接访问 repo、拼 SQL |
| `service` | 编排用例、控制事务边界、调用多个 repo/domain | 直接写 SQL、操作 HTTP 类型 |
| `domain` | 领域模型、不变量校验、纯计算 | 任何 I/O、读配置、读环境变量 |
| `repo` | 执行查询、映射行对象 | 业务规则、跨表业务判断 |

> **repo 的"归属强制注入"**（安全关键）：repo 层的所有查询方法**必须**接收 `subjectId` 参数并在 SQL 中作为条件，不允许"可选传入"。

### 4.2 错误处理

```cangjie
// ✅ 正确：统一错误类型（放 ams-kernel）
// ⚠️ 实测结论（SDK 1.0.5）：
//   ① 枚举构造器只能写「类型」，不能写「参数名: 类型」
//      写成 | ValidationError(field: String) 会编译失败（unclosed delimiter）
//   ② 仓颉的 throw 只能抛 Exception 的子类，**枚举不能被抛出**
//      因此「可抛出的业务错误」必须是 Exception 子类，而非 enum
//   ③ 枚举成员命名遵循官方 cjlint 规则 G.NAM.03：大驼峰（不是 VALIDATION_FAILED）
public enum AppErrorKind {
    | ValidationFailed
    | Unauthorized
    | Forbidden
    | NotFound
    | Conflict
    | RateLimited
    | CryptoFailure
    | StorageFailure
    | DatabaseFailure
    | Internal
}

// ✅ 正确：可抛出的业务异常（Exception 子类），携带错误码与字段
public class AppError <: Exception {
    public let code: String        // 对外错误码（SCREAMING_SNAKE_CASE）
    public let field: String       // 出错字段（可空）

    public init(kind: AppErrorKind, message: String) {
        super(message)
        this.code = kindToCode(kind)
        this.field = ""
    }

    public init(kind: AppErrorKind, field: String, message: String) {
        super(message)
        this.code = kindToCode(kind)
        this.field = field
    }
}

// ⚠️ 仓颉的 enum **没有 toString()**（实测：'toString' is not a member of enum）
//    枚举 → 错误码字符串必须用 match 显式映射
func kindToCode(kind: AppErrorKind): String {
    match (kind) {
        case AppErrorKind.ValidationFailed => "VALIDATION_FAILED"
        case AppErrorKind.Unauthorized    => "UNAUTHORIZED"
        case AppErrorKind.Forbidden       => "FORBIDDEN"
        case AppErrorKind.NotFound        => "NOT_FOUND"
        case AppErrorKind.Conflict        => "CONFLICT"
        case AppErrorKind.RateLimited     => "RATE_LIMITED"
        case AppErrorKind.CryptoFailure   => "CRYPTO_FAILURE"
        case AppErrorKind.StorageFailure  => "STORAGE_FAILURE"
        case AppErrorKind.DatabaseFailure => "DATABASE_FAILURE"
        case AppErrorKind.Internal        => "INTERNAL_ERROR"
    }
}
```

> ✅ **以上代码已在本机 SDK 1.0.5 上实测编译并运行通过**（`cjc final2.cj` → 输出 `code=DATABASE_FAILURE msg=查询失败`）。开发规范中的仓颉示例应以此为基准，修改后须重新实测。

> **为什么不用 enum 承载业务错误**：enum 适合「有限取值、无需携带上下文」的场景（如错误种类枚举）。但仓颉的异常机制要求 `throw` 的对象派生自 `Exception`，所以**能被抛出的错误必须是类**。本项目采用「enum 定义错误种类 + class 承载错误实例」的组合：既保留 `kind` 的可枚举性（便于 `match` 与指标聚合），又能正常抛出。
>
> **错误码到 HTTP 的映射**（见 §4.5）通过 `AppErrorKind` 与 HTTP 状态码的对照表完成，映射表放在 `ams-kernel` 单点维护。

**规约**：
1. **禁止** `catch (e: Exception) { println(e.message) }` 这类吞异常写法
2. 捕获后必须：① 记录带 `trace_id` 的日志 ② 转换为领域错误或重新抛出 ③ **绝不**把内部异常原文返回给客户端
3. 业务可预期的失败用 `AppError` 枚举表达；真正的技术异常向上抛，由全局处理器兜底
4. 异常信息中不得包含 SQL、口令、密钥、敏感字段值

```cangjie
// ❌ 反模式
try {
    let rows = repo.query(sql)
} catch (e: Exception) {
    println("error: ${e.message}")   // 吞异常 + 可能泄漏 SQL
}

// ✅ 正确（实测可编译运行）
try {
    return repo.query(sql)
} catch (e: DatabaseException) {
    Log.error("db.query.failed", "traceId" => ctx.traceId, "error" => sanitize(e.message))
    throw AppError(AppErrorKind.DatabaseFailure, "查询失败")   // 注意：抛的是 class 不是 enum
}
```

> ⚠️ **实测提醒**：`catch` 块内 `return` 与 `throw` 都是合法的（`finally` 仍会先执行），但**抛出对象必须是 `Exception` 子类**。写成 `throw AppError.DatabaseFailure(...)`（枚举）会报 `the object thrown must derive from 'core.Exception'`。

### 4.3 日志

```cangjie
// ✅ 正确：结构化 + 脱敏包装
Log.info("archive.item.created",
    "traceId" => ctx.traceId,
    "uid"      => ctx.userId,
    "itemId"   => item.id,
    "category" => item.category)

// ✅ 敏感字段使用脱敏包装类型（输出时自动脱敏）
Log.info("archive.sensitive.viewed",
    "idCard" => SensitiveValue(item.idCard))   // 输出为 idCard=***(fingerprint:9a3c...)

// ❌ 禁止

```

**规约**：
- **禁止** `println` / `print`（CI 扫描拦截；调试用 `Log.debug`）
- 级别：`ERROR`（需人工介入）/ `WARN`（异常但可自愈）/ `INFO`（关键业务事件）/ `DEBUG`（开发）/ `TRACE`（极端调试，默认关闭）
- 生产环境默认 `INFO`；`DEBUG` 需显式配置开启
- 日志字段名用 `camelCase`，值不做拼接（结构化便于检索）

### 4.4 并发与资源

```cangjie
// ✅ 正确：连接与流的显式释放
let conn = try {
    dataSource.connect()
} catch (e: DatabaseException) {
    throw AppError(AppErrorKind.DatabaseFailure, "获取连接失败")
}
try {
    let stmt = conn.prepareStatement(sql)
    try {
        stmt.set(1, value)
        stmt.execute()
    } finally {
        stmt.close()
    }
} finally {
    conn.close()
}
```

**规约**：
1. 所有需要释放的资源（连接、语句、流、文件句柄）必须用 `try/finally` 或仓颉的 `try (x = ...) {}` 语法包裹
2. `spawn` 出去的并发任务必须**保存句柄**，并在关闭流程中显式结束
3. 定时器（`setTimeout`/`setInterval` 等价物）必须保存句柄并在销毁时清理
4. 禁止在请求处理中执行无界循环或阻塞 IO（超过 100 ms 的 IO 应异步化）
5. 共享可变状态用 `Atomic`/`Mutex` 保护，禁止裸共享变量

### 4.5 错误码与 HTTP 状态映射

> 错误码用**大驼峰**（`AppErrorKind` 枚举成员），对外 JSON 中转为 `SCREAMING_SNAKE_CASE`（如 `VALIDATION_FAILED`）。

| `AppErrorKind` | 对外错误码 | HTTP | 含义 |
| --- | --- | --- | --- |
| `ValidationFailed` | `VALIDATION_FAILED` | 400 | 入参校验失败 |
| `Unauthorized` | `UNAUTHORIZED` | 401 | 未认证/令牌无效 |
| `Forbidden` | `FORBIDDEN` | 403 | 已认证但无权限 |
| `NotFound` | `NOT_FOUND` | 404 | 资源不存在（**仅在已授权范围内返回**，避免存在性泄漏） |
| `Conflict` | `CONFLICT` | 409 | 乐观锁冲突/唯一性冲突 |
| `RateLimited` | `RATE_LIMITED` | 429 | 触发限流（带 `Retry-After`） |
| `PayloadTooLarge` | `PAYLOAD_TOO_LARGE` | 413 | 上传超限 |
| `UnsupportedMediaType` | `UNSUPPORTED_MEDIA_TYPE` | 415 | 文件类型不支持 |
| `CryptoFailure` | `CRYPTO_FAILURE` | 500 | 密码学故障（**fail-closed**，不降级） |
| `StorageFailure` | `STORAGE_FAILURE` | 503 | 存储不可用 |
| `DatabaseFailure` | `DATABASE_FAILURE` | 503 | 数据库不可用 |
| `Internal` | `INTERNAL_ERROR` | 500 | 未预期异常 |

响应体统一：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "请求参数校验失败",
  "traceId": "01J8XKQ9W3M7NP2ZR4T6YH8BVD",
  "details": [
    { "field": "idCard", "reason": "格式不正确" }
  ],
  "timestamp": "2026-10-24T13:45:12.382Z"
}
```

> `message` 是**面向用户**的通用文案（可本地化），**不含**内部细节。内部细节只进日志。

- [ ] 错误响应不含内部堆栈与 SQL
- [ ] 路径拼接后校验前缀（防穿越）
- [ ] 出网请求目标在白名单内（防 SSRF）
- [ ] 反序列化仅使用 JSON，且限制深度与大小
- [ ] 资源在异常路径也被正确释放

## 5. C++ 后端编码规范

### 5.1 适用范围

C++ 代码**仅限** `packages/ams-native/`。其存在理由是性能敏感或生态缺失（见架构 §5.1）。任何新 C++ 代码引入必须回答："为什么不能用仓颉实现？"

### 5.2 编码规约

| 项 | 规约 |
| --- | --- |
| 错误处理 | **禁止**抛 C++ 异常跨越 FFI 边界；所有导出函数返回 `int32_t` 错误码 |
| 内存 | 禁止裸 `new`/`delete`；使用 `std::unique_ptr`/`std::vector`；FFI 边界不传出分配给调用方的指针 |
| 缓冲区 | 所有输出缓冲区由调用方分配，函数先校验容量，不足返回 `AMS_CRYPTO_ERR_ALLOC` |
| 密钥内存 | 敏感缓冲区用完立即 `OPENSSL_cleanse()` 清零 |
| 常量时间 | 摘要/密钥比较使用 `CRYPTO_memcmp`，禁止 `memcmp` 直接比较 |
| 随机数 | 必须用 `RAND_bytes`（CSPRNG），禁止 `rand()` |
| SIMD/汇编 | 需单独评审并有纯软件回退路径 |
| 目标平台 | 必须同时支持 x86_64 与 aarch64；架构特定代码用 `#if defined(__aarch64__)` 隔离 |
| 硬件加速 | 运行时探测，**不可**假定存在；探测失败走软件路径 |
| 测试 | 每个导出函数必须有单元测试 + **KAT（已知答案测试）** |
| 线程安全 | 导出的函数必须**可重入**（不持有全局可变状态）；上下文由调用方持有 |

### 5.3 FFI 兼容性纪律

| 规则 | 说明 |
| --- | --- |
| ABI 版本号 | `AMS_CRYPTO_ABI_VERSION` 每次不兼容变更必须 +1 |
| 只增不改 | 已有导出函数的签名**永不**修改；新增用新函数名 |
| 符号可见性 | 只导出 `ams_crypto_*` 前缀符号（`-fvisibility=hidden`） |
| 仓颉侧绑定 | 绑定层做版本检查；不匹配则**降级到纯仓颉实现**并告警 |
| 跨语言一致性 | C++ 与仓颉实现跑**同一份 KAT 向量**，输出必须逐字节一致 |
| 内存所有权 | 仓颉侧拥有传入/传出缓冲；C++ 侧不持有跨调用指针 |

### 6.4 前端安全

## 7. 接口设计规范

### 7.1 URL 设计

```
/api/v1/{域}/{资源}[/{子资源}[/{id}]]
```

| 规则 | 示例 |
| --- | --- |
| 版本在路径中 | `/api/v1/archives` |
| 资源用复数名词 | `/api/v1/archive-items` |
| 层级不超过 2 层 | `/api/v1/archive-items/{id}/attachments` ✅；`/api/v1/a/b/c/d` ❌ |
| 动作放子资源或用查询参数 | `POST /api/v1/archive-items/{id}/restore` ✅；`PATCH /api/v1/archive-items?action=restore` ❌ |
| 路径参数用 kebab-case 或 UUID | `/api/v1/archive-items/{itemId}` |

### 7.2 HTTP 方法语义

| 方法 | 语义 | 幂等 | 成功码 | 说明 |
| --- | --- | --- | --- | --- |
| `GET` | 查询 | 是 | 200 | 禁止有副作用；参数放 query |
| `POST` | 创建/非幂等动作 | 否 | 201 | 创建类返回 201 + `Location` |
| `PUT` | 全量替换 | 是 | 200 | 需携带完整资源 |
| `PATCH` | 局部更新 | 否* | 200 | 语义化局部更新；带 `version` 做乐观锁 |
| `DELETE` | 删除（逻辑） | 是 | 204 | 二次确认在 UI 层；可撤销场景用软删 |
| `HEAD` | 探测存在 | 是 | 200 | 文件下载前探测 |
| `OPTIONS` | CORS 预检 | 是 | 204 | 框架自动 |

> `POST /login`、`POST /import` 天然非幂等；其余动作尽量设计为幂等（用幂等键，见 §7.6）。

### 7.3 请求与响应格式

**统一响应封装**：

> 下例中的 `/* ... */` 是**占位注释**，用于说明结构；实际 JSON 不支持注释，落地时需替换为真实值或空数组。

```json
{
  "data": { "...": "业务数据" },
  "meta": {
    "traceId": "01J8XKQ9W3M7NP2ZR4T6YH8BVD",
    "timestamp": "2026-10-24T13:45:12.382Z"
  }
}
```

**列表响应**：

```json
{
  "data": [ /* 数组元素，占位 */ ],
  "meta": {
    "traceId": "...",
    "pagination": {
      "limit": 20,
      "nextCursor": "eyJjcmVhdGVkQXQiOiIyMDI2LTEwLTI0VDEzOjQ1OjEyWiIsImlkIjoiMjAwMzQ1NiJ9",
      "hasMore": true
    },
    "total": 1234
  }
}
```

| 规约 | 说明 |
| --- | --- |
| 时间 | ISO-8601 UTC，带 `Z`；前端负责本地化展示 |
| 字段命名 | `camelCase`（与前端 TS 类型直接对应） |
| 枚举 | 字符串码（`"ACTIVE"`），不传数字 |
| 金额 | 用字符串表示避免浮点误差（如 `"1234.56"`），单位在字段名标明 |
| 空值 | 缺失字段**省略**而非传 `null`（除非业务明确区分"空值"与"未设置"） |
| 大整数 ID | 超过 JS `Number.MAX_SAFE_INTEGER` 的 ID 以**字符串**传输（雪花 ID 需注意） |
| 二进制 | 不走 JSON；用独立下载接口或 multipart |

### 7.4 分页

| 方式 | 使用场景 | 参数 |
| --- | --- | --- |
| **游标分页（默认）** | 列表、检索、时间线 | `?limit=20&cursor=<opaque>` |
| 页码分页 | 后台管理类需要跳页的列表 | `?page=3&size=20`（仅限数据量可控场景） |

| 规约 | 说明 |
| --- | --- |
| 游标不透明 | 客户端**不得**解析或构造游标（base64 编码的内部结构） |
| 默认 limit | 20；最大 100（超出按 100 截断或返回 400） |
| 排序稳定 | 游标分页必须有**唯一且稳定**的排序键（`created_at, id` 组合） |
| `total` | 仅在数据量可控时返回；大数据集用 `hasMore` 代替 |

### 7.5 筛选与排序

```
GET /api/v1/archive-items?category=identity,education&status=ACTIVE
    &validFrom=2020-01-01&validTo=2026-12-31
    &q=keyword&tag=urgent
    &sort=updatedAt:desc,createdAt:desc
    &limit=20&cursor=...
```

| 规约 | 说明 |
| --- | --- |
| 参数命名 | `camelCase` |
| 多值 | 逗号分隔（`category=a,b`），或重复参数（`category=a&category=b`）——**统一用逗号分隔** |
| 布尔 | `true`/`false` 字面量，不用 `1`/`0` |
| 日期 | `YYYY-MM-DD` 或 ISO-8601 |
| 排序字段 | **必须白名单**，非法值返回 400（不静默忽略） |
| 排序方向 | `asc`/`desc` |
| 筛选组合 | 同一参数内多值为 OR，不同参数间为 AND（需在 OpenAPI 中明确声明） |

### 7.6 幂等与重放

| 场景 | 机制 |
| --- | --- |
| 写操作重试 | 支持 `Idempotency-Key` 请求头（UUID）；服务端按 `(userId, key)` 缓存 24 h 的响应，重复请求返回首次结果 |
| 导入任务 | 提交时带幂等键；相同键返回已有任务 |
| 导出任务 | 同上 |
| 敏感操作（授权、共享创建） | 幂等键 + 二次口令确认 |

### 7.7 版本化策略

| 变更类型 | 处理 |
| --- | --- |
| 新增可选字段、新增接口 | **兼容变更**，不升版本 |
| 新增必填请求字段、字段语义变更、字段删除 | **破坏性变更** → `/api/v2` |
| 旧版本支持期 | v1 与 v2 并行 ≥ 2 个发布周期；v2 上线时公告 v1 废弃时间表 |
| 废弃流程 | 响应头 `Deprecation: true` + `Sunset: <date>`；监控 v1 调用量，降到阈值以下再下线 |

### 7.8 OpenAPI 契约

| 项 | 要求 |
| --- | --- |
| 规范 | OpenAPI 3.1 |
| 生成 | 由代码注解生成（Cangjie 侧写注解 → CI 生成 `openapi.json`） |
| 位置 | `docs/api/openapi.json`，随版本提交 |
| 门禁 | CI 校验：① 新接口必须有文档 ② 变更需通过 diff 检查 ③ **破坏性变更必须显式标注**（否则 CI 失败） |
| 错误响应 | 所有接口必须声明 4xx/5xx 的错误码 |

## 8. 数据库与 SQL 规范

### 8.1 设计规范

| 项 | 规范 |
| --- | --- |
| 表名 | `snake_case` 复数（`archive_items`、`audit_logs`） |
| 列名 | `snake_case`；布尔用 `is_` 前缀；时间用 `_at` 后缀（`created_at`、`expired_at`） |
| 主键 | `id BIGINT`，雪花 ID（**不用自增**，避免分布式冲突与泄露业务量） |
| 外键 | **不使用物理外键约束**，用逻辑外键 + 应用层保证 + 定期一致性校验（openGauss 的 FK 会带来锁与性能开销） |
| 索引 | 见 `06-数据模型设计.md` §5 |
| 非空 | 业务必需列 `NOT NULL`；可空列必须有默认值或明确语义 |
| 默认值 | `DEFAULT` 用于状态类列（`status SMALLINT NOT NULL DEFAULT 0`） |
| 注释 | 表与列必须有 `COMMENT`（便于运维与文档生成） |
| 字符集 | UTF-8；`varchar` 长度按业务上限设定，不用 `text` 存短字段 |
| 金额 | `NUMERIC(18,2)`，**不用** `float/double` |
| 时间 | `TIMESTAMPTZ`（带时区），统一存 UTC |
| 枚举 | 用 `SMALLINT` + 代码表（**不用** `CHECK` 硬编码字符串列表），见 `06` §7 |
| JSON | 仅用于**真正动态**的字段（扩展字段、审计详情）；能用列表达的不用 JSON |
| 大对象 | 禁止 `BLOB`/`TEXT` 存 > 1 MB；附件走对象存储 |

### 8.2 表命名前缀约定

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `sys_` | 系统与权限 | `sys_users`、`sys_roles` |
| `arc_` | 档案域 | `arc_items`、`arc_attachments` |
| `aud_` | 审计域 | `aud_logs` |
| `cfg_` | 配置与字典 | `cfg_dict_types`、`cfg_dict_items` |
| `job_` | 任务与租约 | `job_leases`、`job_runs` |
| `nft_` | 通知 | `nft_messages` |

### 8.3 SQL 编写规范

```sql
-- ✅ 正确：参数化 + 明确列名 + 归属强制
SELECT id, category, title, status, created_at
FROM   arc_items
WHERE  subject_id = ?
  AND  category IN (?, ?)
  AND  deleted_at IS NULL
ORDER  BY created_at DESC, id DESC
LIMIT  ?;

-- ❌ 错误：字符串拼接（注入风险）
SELECT * FROM arc_items WHERE subject_id = '${subjectId}';
```

| 规约 | 说明 |
| --- | --- |
| 参数化 | 所有值用 `?` 占位；**禁止**任何形式的值拼接 |
| 动态标识符 | 表名/列名/排序方向用**白名单映射**，不接受用户输入直接进入 SQL |
| 列清单 | 不使用 `SELECT *` |
| `IN` 列表 | 长度上限 1000，超出分批 |
| 批量写 | `executemany` 或多值 INSERT，单批 ≤ 1000 行 |
| 事务 | 短事务；**禁止**在事务内做 HTTP 调用或长时间计算 |
| 锁 | 避免 `SELECT ... FOR UPDATE` 长时间持有；必要时不加锁改用乐观锁 |
| 死锁 | 捕获死锁异常并**有限次重试**（≤ 3 次，指数退避） |
| 注释 | 复杂 SQL 加 `--` 说明；临时排障 SQL 标注 `FIXME(owner)` |

### 8.4 迁移脚本规范

| 规约 | 说明 |
| --- | --- |
| 命名 | `V<三位序号>__<snake_case_描述>.sql`，序号只增不减，**已发布脚本不可修改** |
| 幂等 | 每个脚本应可安全重复执行（`IF NOT EXISTS` / `IF EXISTS`） |
| 事务 | 脚本在单事务内执行；失败整体回滚 |
| 校验和 | 执行时记录 SM3 校验和；不匹配则中止启动（防篡改） |
| 破坏性变更 | 拆为多步：先加列 → 双写 → 回填 → 切读 → 删旧列（至少跨两个版本） |
| 大表变更 | `ADD COLUMN` 带默认值且非空时用 `NOT VALID` + 分批 `VALIDATE`（避免长锁） |
| 回滚 | 每个脚本附 `-- rollback:` 说明；自动回滚不保证（DDL 事务性有限） |

### 8.5 慢查询治理

| 项 | 阈值 | 动作 |
| --- | --- | --- |
| 慢 SQL 阈值 | > 1000 ms | 记录到慢查询日志（表名、语句模板、耗时、扫描行数） |
| 告警 | 单分钟 > 5 条慢 SQL | 告警 |
| 治理 | 每迭代清理 Top-N 慢查询 | 纳入 DoD |

## 9. Git 分支与提交规范

### 9.1 分支模型

```
main（受保护，生产分支）
  │
  ├── develop（集成分支，默认目标分支）
  │     │
  │     ├── feature/<域>-<简述>        # 功能
  │     ├── fix/<简述>                  # 缺陷
  │     ├── hotfix/<简述>               # 线上紧急修复
  │     ├── chore/<简述>                # 构建/依赖/配置
  │     └── docs/<简述>                 # 文档
  │
  └── release/<版本号>                  # 发布分支（从 develop 切出）
```

| 分支 | 保护规则 |
| --- | --- |
| `main` | 禁止直接 push；必须 PR + 2 人评审 + 全部 CI 绿 + 标签签名 |
| `develop` | 禁止直接 push；必须 PR + 1 人评审 + CI 绿 |
| `release/*` | 只接受 bugfix；禁止新功能 |
| `feature/*` | 从 `develop` 切出，合并回 `develop`（**squash merge**） |
| `hotfix/*` | 从 `main` 切出，合并回 `main` **与** `develop` |

### 9.2 提交信息规范（Conventional Commits）

```
<type>(<scope>): <subject>

<body>

<footer>
```

| type | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(archive): add idCard blind index lookup` |
| `fix` | 缺陷修复 | `fix(auth): reject expired refresh token reuse` |
| `refactor` | 重构（不改行为） | `refactor(repo): extract cursor pagination helper` |
| `perf` | 性能优化 | `perf(crypto): use native SM4 provider when available` |
| `docs` | 文档 | `docs(api): document share link endpoints` |
| `test` | 测试 | `test(authz): add cross-subject access matrix` |
| `build` | 构建/依赖 | `build(deps): pin opengauss-driver to v1.1.3` |
| `ci` | CI 配置 | `ci: add arm64 build matrix` |
| `chore` | 杂项 | `chore: update gitignore` |
| `revert` | 回滚 | `revert: revert "feat(share): add link expiry"'` |

| 字段 | 规则 |
| --- | --- |
| scope | 模块名（`archive`/`auth`/`crypto`/`storage`/`web`/`infra`） |
| subject | ≤ 50 字符，祈使句，首字母小写，句末无句号 |
| body | 每行 ≤ 72 字符，说明"为什么"而非"做了什么" |
| footer | `BREAKING CHANGE:` / `Closes #123` / `Refs D-004` |
| 语言 | 英文（便于国际协作与工具解析） |

### 9.3 PR 规范

| 项 | 要求 |
| --- | --- |
| 标题 | 遵循 Conventional Commits |
| 描述 | 必须包含：变更目的、变更内容、影响范围、测试情况、关联需求（`FR-xxx`）或 ADR |
| 规模 | 建议 ≤ 500 行；超出需说明原因（拆分优先） |
| 关联 | 用 `Closes #123` 关联 Issue；架构性变更需引用 `ADR-xxx` |
| 合并方式 | `feature/*` → `develop`：**squash merge**；`release/*` → `main`：**merge commit**（保留发布节点） |
| 冲突 | 由作者解决；禁止在冲突解决时混入无关改动 |

## 10. 代码审查与静态检查

### 10.1 评审要求

| 变更类型 | 最少评审人 | 必须含 |
| --- | --- | --- |
| 普通功能 | 1 | 同模块熟悉者 |
| 安全敏感模块（`ams-security`、`ams-crypto`、审计、导出、分享） | 2 | **安全负责人** |
| 数据模型变更（迁移脚本） | 2 | 后端负责人 + DBA 角色 |
| 架构变更（跨包依赖、新增基础设施依赖） | 2 | 架构负责人 |
| CI/构建/部署脚本 | 1 | 运维负责人 |

### 10.2 评审检查清单（评审人逐项确认）

**通用**
- [ ] 变更是否解决了对应需求（能指出 `FR-xxx`）
- [ ] 是否引入了未声明的依赖或新的抽象层
- [ ] 错误处理是否完整（无吞异常、无裸 `catch`）
- [ ] 是否有硬编码的魔法值/密钥/URL
- [ ] 并发安全（共享状态、竞态、重复提交）
- [ ] 资源释放（异常路径也释放）

**安全**
- [ ] 输入校验是否完整且在服务端执行
- [ ] SQL 是否全部参数化
- [ ] 输出是否转义（XSS）
- [ ] 权限点与归属校验是否覆盖新接口
- [ ] 敏感字段是否加密落库、日志是否脱敏
- [ ] 新接口是否在 OpenAPI 中声明且标注了所需权限点

**数据**
- [ ] 迁移脚本是否幂等、是否可回滚、是否影响大表
- [ ] 索引是否配套（新增查询条件需配套索引）
- [ ] 是否需要补充审计（新增敏感操作）

**测试**
- [ ] 新增逻辑是否有对应测试
- [ ] 测试是否验证了**行为**而非实现细节
- [ ] 边界与异常路径是否被覆盖

### 10.3 静态检查门禁

| 检查 | 工具 | 阻断级别 |
| --- | --- | --- |
| 仓颉格式化 | `cjfmt -d <src>` 后 `git diff --exit-code` 判差异（cjfmt 无 `--check` 选项） | error |
| 仓颉静态检查 | `cjlint -f <src> -r json -o ./report`（或 `cjpm build -l`） | error 阻断；warn 记录但不阻断（须登记 TODO） |
| 仓颉测试 | `cjpm test` | error |
| C++ 格式化 | `clang-format --dry-run` | error |
| C++ 静态检查 | `clang-tidy` | error |
| C++ 单元测试 | ctest | error |
| C++ 内存检查 | ASan/UBSan（CI 夜间任务） | error |
| 前端 lint | ESLint | error |
| 前端类型检查 | `tsc --noEmit` | error |
| 前端单测 | Vitest | error |
| 前端构建 | `vite build` | error |
| 依赖漏洞 | SCA 扫描 | 高危/严重阻断 |
| 密钥泄露 | Gitleaks | error |
| 覆盖率 | `cjpm test --coverage` + `cjcov --root=./ --html-details -o html_output` | 低于阈值阻断（见 §11.4） |
| 迁移脚本 | 校验和 + 幂等性检查 | error |

### 10.4 CI 流水线阶段

```
① lint & format ──► ② unit test ──► ③ build (matrix) ──► ④ integration test
      │                                                          │
      └────────────────► ⑤ security scan ◄───────────────────────┘
                              │
                              ▼
                     ⑥ e2e (staging) ──► ⑦ package ──► ⑧ publish (on tag)
```

**快速通道**：PR 触发 ①~④（目标 < 8 分钟）；`main`/`release` 触发全部；夜间触发全矩阵 + 模糊测试 + 深度安全扫描。

## 11. 测试规范

### 11.1 测试层次与职责

| 层次 | 范围 | 工具 | 位置 | 运行时机 |
| --- | --- | --- | --- | --- |
| **单元测试** | 单一函数/类/模块 | `cjpm test`（仓颉）、Vitest（前端）、ctest（C++） | `test/` 与 `src` 同级 | 每次提交 |
| **集成测试** | 多个模块协同（含真实 DB） | `cjpm test` + Testcontainers 风格 DB 容器 | `test/integration/` | 每次 PR |
| **契约测试** | 接口与 OpenAPI 一致 | 契约测试框架 | `test/contract/` | 每次 PR |
| **E2E** | 用户完整旅程 | Playwright | `web/tests/e2e/` | 每次 PR（关键路径）+ 发布前（全量） |
| **性能测试** | 关键接口与并发 | k6 / wrk | `test/perf/` | 发布前 + 每里程碑 |
| **安全测试** | 注入/越权/加密一致性 | 自建套件 + ZAP | `test/security/` | 每次 PR + 渗透测试 |
| **恢复测试** | 备份恢复演练 | 脚本 | `test/dr/` | 每月 |

### 11.2 命名与结构

```
测试函数命名：test<被测行为>_<场景>_<预期>
例：testLogin_whenPasswordWrong_returnsUnauthorized
    testBlindIndex_whenNormalizedSame_returnsSameHash
```

**规约**：
1. 测试名必须表达**行为与预期**，禁止 `test1`、`testFoo`
2. 一个测试只断言一个行为（多断言需是同一行为的组成部分）
3. 测试必须**独立**（不依赖执行顺序、不依赖共享可变状态）
4. 测试数据用工厂函数/Fixture 生成，不用固定魔法值
5. 时间相关测试注入**可控时钟**，禁止 `sleep` 等待真实时间
6. 网络调用必须 mock 或用容器化依赖，禁止依赖公网

### 11.3 各层具体要求

**单元测试**
- 覆盖所有分支与边界；错误路径**必须**有测试
- 领域层（`ams-core`）追求 100% 分支覆盖（无 I/O，成本低）
- 安全关键模块（`ams-crypto`、`ams-security/authz`）要求 100% 行覆盖

**集成测试**
- 使用**真实 openGauss 容器**（非 mock），验证 SQL 正确性、索引使用、事务行为
- 每个仓储方法至少一条真实查询测试
- 迁移脚本有"从零升级"与"从上一版本升级"两条路径的测试

**E2E**
- 覆盖 PRD §7.2 的 16 条核心清单
- 使用**真实登录态**（真实 API 登录，不 mock 鉴权）
- 每个测试自带唯一测试数据与清理逻辑（用 `test_run_id` 前缀隔离）
- 断言**用户可见结果**，不依赖内部实现

**性能测试**
- 固定数据集规模（1 万 / 10 万 / 100 万条）
- 记录 P50/P95/P99，不只看平均值
- 与 NFR 目标对比，**未达标不允许发布**

### 11.4 覆盖率要求

| 模块 | 行覆盖 | 分支覆盖 | 说明 |
| --- | --- | --- | --- |
| `ams-crypto` | 100% | 100% | 安全关键 |
| `ams-security` | ≥ 95% | ≥ 90% | 安全关键 |
| `ams-core` | ≥ 90% | ≥ 85% | 领域逻辑 |
| `ams-data` | ≥ 80% | ≥ 70% | 仓储层 |
| `ams-app` | ≥ 75% | ≥ 65% | 编排层 |
| `ams-api` | ≥ 70% | ≥ 60% | 适配层 |
| `ams-server` | ≥ 60% | ≥ 50% | 启动与装配 |
| 前端 `features/` | ≥ 75% | ≥ 65% | — |
| 前端 `components/` | ≥ 60% | ≥ 50% | — |
| C++ 插件 | 100%（含 KAT） | 100% | 安全关键 |

**整体门槛**：后端 ≥ 70%、前端 ≥ 70%。低于阈值的 PR 不允许合并。

> **覆盖率的正确用法**：覆盖率是**下限门槛**而非目标。100% 覆盖但断言弱的测试比 60% 覆盖且断言强的测试更危险。评审时需检查断言质量（见 §11.5）。

### 11.5 断言质量要求

| 反模式 | 问题 | 正确做法 |
| --- | --- | --- |
| `assertTrue(result != null)` | 太弱，错误实现也能通过 | 断言具体值或具体错误码 |
| `assertEquals(200, status)` 但不校验响应体 | 漏检数据错误 | 同时校验响应体关键字段 |
| 大量 `assertNotNull` | 无信息量 | 断言行为结果 |
| 只测正常路径 | 遗漏真实缺陷来源 | 每个功能配 ≥ 1 个异常路径测试 |
| mock 掉被测逻辑 | 测试失去意义 | 只 mock 边界（网络/DB/时间），不 mock 被测逻辑 |

## 12. 日志与可观测性规范

### 12.1 日志字段规范

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `ts` | ✓ | ISO-8601 UTC |
| `level` | ✓ | ERROR/WARN/INFO/DEBUG/TRACE |
| `traceId` | ✓ | 全链路追踪 ID |
| `module` | ✓ | 模块名 |
| `action` | ✓ | 动作码 |
| `result` | ✓ | OK/FAIL |
| `durationMs` | 关键路径 ✓ | 耗时 |
| `uid` | 视场景 | 操作者 |
| `clientIp` | 视场景 | 客户端 IP |

### 12.2 禁止记录的内容

- 口令、令牌、密钥、验证码、分享口令
- 完整证件号、手机号、银行卡号、邮箱、住址（用指纹代替）
- 请求体中的敏感对象（登录/注册/改密接口整体不记录）
- SQL 参数值
- 异常堆栈中未经脱敏的内容

### 12.3 链路追踪

| 项 | 规则 |
| --- | --- |
| `traceId` 生成 | 网关生成（或接受上游 `X-Trace-Id`），透传到后端 → DB 日志 → 前端响应体 |
| 前端持有 | 响应体 `meta.traceId` 返回给前端，用于用户报障时快速定位 |
| 存储 | 日志中带 `traceId`，可按此检索全链路 |

### 12.4 指标命名

```
ams_<subsystem>_<metric>_<unit>
例：ams_http_request_duration_seconds
    ams_db_pool_connections
    ams_login_failure_total
```

**禁止**在指标标签中使用高基数值（用户 ID、请求 ID、完整路径）——会造成时序库膨胀。路由标签用**路由模板**（`/api/v1/archive-items/{id}`）而非实际路径。

## 13. 配置与密钥管理规范

### 13.1 配置分层

```
代码内默认值 → application.toml → application.{env}.toml → 环境变量 → 外部配置源
```

| 规约 | 说明 |
| --- | --- |
| 环境变量覆盖 | 环境变量名 `AMS_` 前缀，嵌套用 `__` 分隔（`AMS_DB__POOL__MAXSIZE=80`） |
| 敏感项禁止入配置 | 口令、密钥、令牌**不入**配置文件（配置会进版本库与镜像） |
| 密钥来源 | 仅允许：密钥文件路径（`AMS_KEYSTORE_PATH`）或 KMS |
| 变更审计 | 配置变更走管理接口（写审计）或改文件（由部署流程记录） |
| 校验 | 启动时校验配置合法性；缺失必填项 → 拒绝启动并给出清晰提示 |

### 13.2 密钥规范

| 规约 | 说明 |
| --- | --- |
| 存放 | 独立目录，权限 `0700`；文件 `0600` |
| 严禁 | 进 Git、进镜像、进日志、进备份明文、进 CI 变量明文 |
| 生成 | 启动时 CSPRNG 生成；或由运维用 `ams-admin keygen` 离线生成 |
| 轮换 | 支持在线重包裹（不需重加密数据），见安全章 §4.6.2 |
| 备份 | 至少两份离线副本，与业务 KEK 分离保管 |
| 泄露应急 | 立即 `rotate` → 吊销旧版本 → 重包裹 → 评估是否需重加密数据 |

## 14. 违规处理

| 级别 | 情形 | 处理 |
| --- | --- | --- |
| 🔴 阻断 | 提交密钥/SQL 注入/XSS 漏洞/权限绕过/敏感信息落库 | **拒绝合并**；立即修复；安全负责人复核 |
| 🟠 严重 | 违反分层依赖、无测试的关键逻辑、硬编码密钥类信息、缺少审计的敏感操作 | 拒绝合并；补齐后重审 |
| 🟡 一般 | 命名/格式/分层风格问题 | 拒绝合并（CI 自动拦截）或限期整改 |
| 🟢 建议 | 代码质量建议 | 记录 TODO，不阻断 |

**豁免流程**：确需违反规范时，提交 ADR 说明理由与补偿措施，经架构组（安全相关需安全负责人）批准，登记到 `docs/exceptions.md`，并设定整改期限。
