### 单测与端到端抓出的三个真实缺陷

| 缺陷 | 表现 | 根因 |
| --- | --- | --- |
| 邀请码被写成 ASCII 码 | 生成 `"5051525354555657"`，`isWellFormed` 恒失败 → 建邀请必报 `Internal` | `String` 下标返回 `Byte` 而非 `Rune`，`sb.append(Byte)` 命中 `append(Int64)` 重载 |
| `acceptInvite` 恒报「HMAC 密钥不能为空」 | 落地页正常、接受邀请必挂 | `findByTokenHash` 的 SELECT 漏取 `code_hash` / `code_salt`，`RowData.str()` 对缺失列返回空串 |
| 权限种子授给不存在的角色 | 迁移「成功」但除 `owner` 外谁都建不了组 | 种子写 `r.code = 'user'`，而实际角色是 `owner/curator/family/org_admin/auditor` |

> 三个缺陷的共同点：**都不报编译错、也不会自然暴露**，只能靠「给定输入 → 断言输出」或真实 HTTP 调用才能发现。
> 这也是为什么本轮坚持「先补单测 + 端到端，再宣布完成」。
