## 1. 文档目的与范围

### 1.1 目的

本 PRD 定义 AMS 的业务范围、用户角色、功能优先级、验收标准与非功能指标，作为设计、开发、测试三方共同的事实基准（single source of truth）。任何与本 PRD 不一致的实现均视为缺陷；确需变更时按 §1.3 流程处理。

### 1.2 范围

**包含**
- 个人/家庭全生命周期数字档案的分类归档、检索、版本管理
- 账号体系：注册、登录、会话、RBAC 授权
- 高安全等级防护体系（详见 `03-安全设计专章.md`）
- Web 端响应式界面，含深浅色主题
- Linux / Windows 二进制与 Docker 双形态交付，x86_64 / aarch64 双架构

**不包含（本期）**
- 移动原生 App（仅响应式 Web）
- 跨机构数据交换与联邦身份
- 电子签名与法律效力认证
- 人脸识别、活体检测等生物特征能力
- 多租户 SaaS 计费与在线支付

### 1.3 需求变更流程

```
需求提出 → 产品登记入需求池 → 评估影响(工作量/架构/安全)
        → 架构组评审 → 决策: 接受/拒绝/延期
        → 更新本 PRD 编号与版本 → 通知全体 → 同步追溯矩阵
```

变更需同步更新：本文档、追溯矩阵（§9）、对应设计文档（02/03/06）、测试用例集、排期表（05）。

## 2. 产品概述

### 2.1 背景与问题

个人/家庭的关键信息（证件、学历、职业资格、资产、健康、亲属关系）长期散落在钱包、相册、纸质文件、聊天记录与各平台账号中。典型痛点：

| 痛点 | 具体表现 | 后果 |
| --- | --- | --- |
| 分散 | 证件照在手机相册，证书在邮箱附件，房产证在抽屉 | 需要时找不到，丢失不可恢复 |
| 无版本 | 同一份简历有 8 个副本，不确定哪个最新 | 误用过期证件导致业务受阻 |
| 检索弱 | 文件名 `IMG_20230115_final(2).jpg` | 无法按"2021 年取得的中级会计师"检索 |
| 无授权 | 把整个网盘/电脑借给别人 = 全部隐私泄露 | 过度授权，无最小化披露能力 |
| 无留痕 | 谁看过我的档案、谁改过我的信息，无从查证 | 家庭/代管场景纠纷无法举证 |
| 不可迁移 | 换手机/换平台，数据带不走 | 被平台锁定 |

### 2.2 产品定位

> **AMS = 你的私人档案保险柜 + 可检索的知识库 + 可举证的安全记录本。**

三大支柱：
1. **收得全** —— 结构化分类体系 + 影像附件，覆盖人生各维度
2. **找得到** —— 结构化筛选 + 中文全文检索 + 标签体系 + 盲索引等值检索
3. **控得住** —— 字段级国密加密 + RBAC + 附件版本 + 全链路审计

### 2.3 竞争与差异化

| 方案 | 优势 | 短板 | AMS 取舍 |
| --- | --- | --- | --- |
| 网盘（云盘） | 容量大、文件多 | 无结构、检索弱、不可授权到字段粒度 | 结构化档案模型 + 附件作为从属资源 |
| 密码管理器 | 高安全、强加密 | 只存凭据，不存档案 | 借鉴其密钥与加密工程实践，扩展到全量档案 |
| 纸质档案袋 | 物理可信 | 检索几乎为零、易损 | 保留"版本与留痕"的仪式感，数字化实现 |
| 政务民生 App | 数据权威 | 覆盖不全、不可自定义、无导出权 | 分类体系可自定义 + 完全数据自持 |

**核心差异化**：开源、可私有化部署、国密合规、字段级可授权、附件版本化与操作可举证。

### 2.4 成功指标

| 层级 | 指标 | 目标值 | 观测方式 |
| --- | --- | --- | --- |
| 采纳 | 注册后 7 日内录入 ≥ 5 条档案的用户占比 | ≥ 60% | 埋点 + 数据库统计 |
| 采纳 | 30 日留存率 | ≥ 45% | 同上 |
| 效率 | 单条档案录入平均耗时 | ≤ 90 秒（不含附件上传） | 前端埋点 |
| 效率 | 检索到目标条目的 P95 响应 | ≤ 800 ms | 接口压测 |
| 信任 | 审计日志覆盖率（敏感操作写入率） | 100%（不可有缺口） | 自动化断言 + 抽样审计 |
| 安全 | 高危/严重漏洞 | 0 个（上线前） | 渗透测试报告 |
| 可靠性 | 服务可用性 | ≥ 99.9%（工作时段） | 监控统计 |

### 3.3 跨角色通用需求

所有角色共同要求：
- 界面在手机到 4K 显示器上都可用，**深浅色主题**跟随系统且可手动覆盖
- 关键操作有**即时反馈**（按下即响应，而非松手才响应）
- 危险操作（删除、导出全部、授权他人）**二次确认**且提供撤销窗口
- 所有时间以本地时区展示，存储统一 UTC

### 4.2 关键用户故事（含验收要点）

#### SC-02 · 分类归档录入

**主故事**
> 作为档案所有者，我希望按"学历"分类新建一条学历档案，填写学校、专业、起止时间、学号，并上传学位证扫描件，以便日后按"学位"或"2018"检索到它。

**验收要点**
1. 分类下拉支持 11 类档案，每类有独立表单模板（字段动态渲染）。
2. 同一分类可定义**自定义扩展字段**（文本/数字/日期/单选/多选/布尔）。
3. 附件上传支持 JPG/PNG/PDF，单文件 ≤ 50 MB；**上传后立刻计算 SM3 指纹**并用于秒传去重。
4. 证件号、手机号等敏感字段在表单中输入即加密（客户端 SM4 加密由后端密钥协商，见安全章），列表页默认脱敏显示，点击"显示完整"需二次校验并留痕。
5. 保存成功后条目进入"已归档"，其所属主体档案计数 +1，列表顶部时间线出现该条目。
6. 中途放弃（关闭弹层）时，已填内容以草稿保留 24 小时，可从"草稿箱"恢复。

**异常与边界**
- 附件格式不符/超限：就地提示，不清空已填表单
- 网络中断：附件分片续传（每片 5 MB，保留 24 小时）
- 唯一性冲突（如同一证件号重复）：提示"已存在相同证件号条目，是否关联/查看"，不直接拒绝

#### SC-04 · 多维检索

**主故事**
> 作为档案所有者，我希望输入"中级会计师"或"2021"，或组合筛选"分类=资质证书 且 有效期已过期"，快速定位目标条目。

**验收要点**
1. 关键词走**中文全文检索**（openGauss 分词 + GIN 索引），覆盖标题、备注、自定义字段的文本值。
2. 结构化筛选：分类、标签、状态、颁发机构、时间区间、布尔值自定义字段，多条件 AND/OR 组合。
3. 排序：更新时间、创建时间、条目名称、有效期（升降序）。
4. 结果分页游标化（cursor-based），深翻页性能不衰减。
5. **盲索引等值检索**：证件号/手机号精确匹配走盲索引列，命中且响应 ≤ 300 ms。
6. 命中片段高亮（关键词上下文），敏感字段命中默认掩码显示。

#### SC-07 · 授权共享

**主故事**
> 作为档案所有者，我希望生成一个 7 天有效、带访问密码、可随时撤销的链接，把"我的身份证正反面"发给家人；对方打开时需要输入密码，且我能看到谁在什么时候打开过。

**验收要点**
1. 链接粒度：**单条目** 或 **单分类**，不支持"整个系统"。
2. 可配置：有效期（1/7/30 天）、访问密码（≥6 位）、是否允许下载、是否加水印（动态水印含访问者标识与时间）、最大访问次数。
3. 每次访问记录：时间、IP、User-Agent、成功/失败、失败原因。
4. 撤销后立即失效（服务端校验，不依赖前端）。
5. 水印为**服务端渲染**（对图片与 PDF 叠加），防前端绕过。

#### SC-09 · 数据导出与可携带

**主故事**
> 作为档案所有者，我希望把"我的全部学历档案"导出成一个加密压缩包（含附件与清单），能下载到本地保存或交给家人保管；等我不再需要时，能一键删除这个包。

**验收要点**
1. 提交导出后**立即返回任务 ID**（202），页面显示进度（已处理/总数）；完成后站内通知 + 邮件推送下载入口。
2. 导出包为 `AMS-EXPORT-1` 格式：包含 `manifest.json`（清单）、条目元数据、附件（逐件 SM4 加密）、包签名；**整个包再整体加密**。
3. 包口令由用户口令派生，**用户遗忘则包不可恢复** —— 提交前必须明确提示。
4. 敏感字段**默认导出为密文原样**；用户可勾选"导出明文"，此时需二次确认（重新输入口令）且触发实时告警。
5. 健康/资产等 `high` 敏感分类导出需**额外授权** + 二次确认 + 实时告警，且默认不含附件。
6. 下载需重新鉴权；产物默认 7 天过期自动删除，删除动作写审计。
7. 用户可随时撤销/删除产物；撤销后立即失效（服务端校验，不依赖定时任务）。
8. 导出包可被重新导入（回导闭环）：导入时逐件校验 SM3 指纹，验签失败或指纹不符则拒绝。

**异常与边界**
- 导出范围超过单任务上限（5000 条）：提示拆分，不静默截断
- 部分条目/附件读取失败：任务标"部分成功"，清单明确列出失败项，**不静默丢弃**
- 触发限流：返回 429 + `Retry-After`，不创建任务
- 任务中途实例崩溃：租约过期后自动重新调度，不产生重复产物

> 完整安全规则见安全专章 §6.5。

#### SC-10 · 审计查询与举证

**主故事**
> 作为安全审计员，我希望查询"某用户在某时间段对某主体的全部操作"，并导出一份带哈希链校验的可信报告。

**验收要点**
1. 审计记录字段固定（见安全章 §6.2），含 `prev_hash` 形成哈希链，链断可检测。
2. 支持按：操作者、主体、分类、操作类型、时间范围、结果、IP 多维过滤。
3. 导出报告包含：记录明细 + 链校验结论（`链完整 / 第 N 条起断裂`）。
4. 审计记录**不可修改、不可删除**；查询行为本身也写审计（自审计）。
5. 高敏操作（授权、导出、密钥轮换、权限变更）在管理后台实时告警。

### 5.4 权限与角色模型（FR-ACL）

**权限模型**：`用户 → 角色 → 权限`（RBAC）+ `数据归属（ownership）` 双层判定。

```
有效权限 = 角色授予的权限 ∩ 数据归属允许的操作
```

判定顺序（详见安全专章 §6.1）：
1. 拥有 `*:own` 权限 → 仅可操作**本人主体**下的资源
2. 拥有 `*:any` 权限 → 可操作**任意主体**的资源（显式越权，如机构管理员、审计员）
3. 二者都无 → 需存在**针对该资源/主体的显式授权记录**（`acl_grants`，如代管人、临时授权）

> 换言之：`archive:read:own` 与 `archive:read:any` 是**互斥的两条路径**，不是同一路径的强弱档位 —— 拥有 `any` 即表示放弃归属约束，因此**不叠加** `own` 的判定。

#### 导出接口契约

```
POST   /api/v1/exports                       # 提交导出任务（异步）
       body: { scope, subjectId, category?, itemIds?, includeAttachments, decryptSensitive, format }
       header: Idempotency-Key（可选）
       resp: 202 { data: { taskId, status: "QUEUED" } }

GET    /api/v1/exports/{taskId}              # 查询任务状态与进度
       resp: 200 { data: { taskId, status, processedCount, totalCount, successCount, failedCount, expiresAt } }

GET    /api/v1/exports/{taskId}/download     # 下载产物（需重新鉴权）
       resp: 二进制流 + Content-Disposition

DELETE /api/v1/exports/{taskId}              # 撤销 / 删除产物
       resp: 204
```

| 状态码 | 场景 |
| --- | --- |
| 202 | 任务已受理 |
| 403 | 无导出权限 / 缺少二次确认令牌 / 分类未获授权 |
| 409 | 幂等键冲突但参数不同 |
| 413 | 导出范围超过单任务上限 |
| 429 | 触发导出限流 |
| 503 | 导出队列已满 |

### 6.2 状态机

#### 6.2.1 账号状态

| 当前状态 | 事件 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| （无） | 注册 | `pending` | 未激活，不可登录 |
| `pending` | 激活设密 | `active` | 发放初始密钥材料 |
| `active` | 连续失败 ≥ 阈值 | `locked` | 临时锁定，指数退避自动解锁 |
| `active` | 管理员锁定 | `locked_perm` | 需管理员解锁 |
| `locked` | 退避时间到 / 解锁 | `active` | — |
| `active` | 登出 | `active` | 仅会话失效，账号不变 |
| `active` | 注销申请 | `pending_delete` | 冷静期（默认 7 天） |
| `pending_delete` | 冷静期内恢复 | `active` | — |
| `pending_delete` | 冷静期届满 | `deleted` | 数据匿名化 + 审计保留 |

#### 6.2.2 档案条目状态

```
        ┌────────┐  保存并归档   ┌────────┐
        │ draft  │──────────────►│ active │──┐
        └───┬────┘               └───┬────┘  │ 归档(冻结编辑)
            │ 编辑                  │ 编辑   │
            │◄─────────────────────┘       ▼
            │                        ┌─────────┐
            │                        │ archived │（只读+可解锁）
            │                        └────┬────┘
            │                             │ 恢复编辑
            ▼                             │
        ┌─────────┐  回收站保留30天  ┌────┴────┐
        │ deleted │◄────────────────│  active  │
        └────┬────┘                 └─────────┘
             │ 30天到期 → 物理清理（写审计）
             ▼
        [物理清理]  审计记录保留，不清理
```

#### 6.2.3 附件状态

| 状态 | 含义 | 流转 |
| --- | --- | --- |
| `uploading` | 客户端上传中 | → `scanning` |
| `scanning` | 服务端扫描与指纹计算中 | → `ready` / `quarantined` |
| `ready` | 可用 | → `deleted`（逻辑删除，保留版本记录） |
| `quarantined` | 命中安全策略，隔离 | 管理员可 `→ ready`（放行）或 `→ deleted` |
| `superseded` | 非当前版本（被新版本取代） | 保留，可回滚为当前版本 |
| `deleted` | 已删除 | 物理清理策略后移除字节流 |

#### 6.2.4 分享/授权状态

`pending`（待接受）→ `active`（生效中）→ `expired`（到期）/ `revoked`（撤销）/ `exhausted`（次数用尽）
服务端每次校验时即时判定，**不依赖定时任务**做失效。

### 6.3 关键流程的异常与补偿

| 流程 | 异常 | 处理策略 |
| --- | --- | --- |
| 附件上传 | 中途中断 | 分片续传，24 h 内保留分片 |
| 附件上传 | 扫描命中 | 置 `quarantined`，通知上传者 |
| 条目保存 | 乐观锁冲突 | 返回 409 + 差异对比，用户选择覆盖/合并 |
| 敏感字段加密 | 密钥服务不可用 | **失败关闭**（fail-closed），拒绝写入，不降级为明文 |
| 导入任务 | 部分行失败 | 事务性：仅成功行入库并生成导入报告；不产生半截数据 |
| 令牌刷新 | 检测到重放 | 立即吊销该用户全部会话 + 告警 + 强制重新认证 |
| 审计写库失败 | DB 异常 | 进入本地 WAL 重试队列；高危操作**同步阻塞**直至落盘成功 |
| 导出 | 大批量导出超时 | 转为异步任务 + 站内通知下载 |

| NFR-PERF-007 | 附件下载首字节 | ≤ 300 ms | 50 MB 文件，服务端流式解密 |
| NFR-PERF-008 | 写操作 P95 | ≤ 500 ms | 含加密与审计落库 |
| NFR-PERF-009 | 前端首屏可交互 | ≤ 1.5 s（4G 模拟，中端安卓） | 生产构建 + gzip |
| NFR-PERF-010 | 密码学吞吐 | SM4 ≥ 500 MB/s；SM3 ≥ 800 MB/s（单核） | 硬件加速可用时更高 |

> **PBKDF2 迭代与延迟的权衡**：口令校验必须慢，但登录需快。方案：迭代次数随硬件能力自适应（基准测试 + 校准，首次部署测量并落库 `kdf_cost`），目标单次校验 ≤ 150 ms；同时对登录接口单独限流并允许"首次失败即引入计算延迟"以拖慢撞库。

## 10. 边界与非目标

### 10.1 本期明确不做（Won't）

| 项 | 原因 | 未来演进点 |
| --- | --- | --- |
| 移动原生 App | 需独立团队与发版链路；响应式 Web 覆盖 80% 场景 | PWA → Native |
| 电子签名/时间戳 | 涉及 CA 与法律效力认定，超出产品边界 | 预留 `signature` 扩展字段 |
| 生物识别 | 隐私合规成本极高 | 预留人脸**照片**作为普通附件 |
| 开放 API 生态与 OAuth 托管 | 本期定位私有化部署内部系统 | 预留 `/api/v1` 版本化与令牌作用域 |
| 多租户计费 | 私有化交付为主 | 数据模型预留 `tenant_id` 可空列 |
| 全文 OCR | 需引入 OCR 引擎，且涉及隐私同意 | P2 已规划 |
| 自动数据同步（云盘/相册） | 各平台 API 不稳定，隐私授权复杂 | P3 预留导入器 SPI |

### 10.2 假设与依赖

| 编号 | 假设 | 若不成立的影响 | 缓解 |
| --- | --- | --- | --- |
| AS-01 | 交付环境可提供 openGauss 实例（≥5.0） | 开发与测试受阻 | 支持 Docker 起单机实例；提供初始化脚本 |
| AS-02 | 存在对象存储或可使用本地 FS | 附件能力受限 | 存储适配层双实现 |
| AS-03 | 甲方接受"密码学复杂度高于通用产品"（登录略慢） | 用户体验投诉 | 自适应迭代 + 首次登录教育 + 后台可调 |
| AS-04 | 鲲鹏部署时存在可用的国密库/TEE 或接受软件实现 | 国密性能不及预期 | 抽象密码学 Provider，支持替换为硬件实现 |
| AS-05 | 有专职或兼职安全评审资源 | 高危漏检 | 至少 1 人具备安全评审资质，外部渗透测试预算列入 |
