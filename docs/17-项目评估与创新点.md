## 二、商业价值

### 2.1 是否能够区分商业版本和社区版本

**判定：🔴 未做 —— 全仓 0 命中，当前为单一版本。**

证据：
- 「商业版 / 社区版 / SKU / 付费墙 / 企业版 / 版本区分」在 `README.md`、`docs/`、`*.md`
  中**精确词 0 命中**。
- 现状只有一种交付形态：`LICENSE`（Apache-2.0）+ 单一发布包
  `ams-release-1.3.0-windows-x86_64.zip`；无功能开关、无授权等级、无许可证校验。

如实边界：
- `README.md:453` 的「允许商业使用」是**许可证条款**，不是版本划分；
  `deploy/compose/docker-compose.yml:33` 的「openGauss 社区镜像」是上游制品名，与版本策略无关。
- **这是待决策项，不是技术债**。若需要划分，可选路径（本文只列方案、不代甲方拍板）：
  - **A 不划分（当前，维持）**：单一版本，商业价值靠服务 / 部署 / 支持交付。
  - **B 功能分层**：社区版 = 私有化全功能，商业版 = 多租户运营、SLA、审计增强、集中管控；
    需引入构建期 feature flag 与许可证校验，会改变「单一版本零回归」现状。
  - **C 服务分层**：代码全量开源，商业版只卖托管 / 订阅 / 技术支持，代码层零改动，
    与 Apache-2.0 最相容，但依赖 SaaS 底座（见 2.2）。
- 与许可证的兼容性提示：Apache-2.0 **允许**闭源衍生，但商标、托管服务条款需另定；
  若采用 B，须保留归属与 NOTICE（`scripts/package.sh` 已强制随包分发 LICENSE）。

## 三、技术栈选择

### 3.1 信创项目

#### 3.1.1 是否有对应的国家标准参考

**判定：✅ 有明确标准号与条款映射。**

证据：
- `docs/13-信创与国家密码标准参考.md:14-29`（§1 算法标准对照）：
  **GB/T 32905-2016**（SM3）、**GB/T 32907-2016**（SM4）、
  **GB/T 32918-2016**（SM2，1~5）、**GM/T 0002 / 0003 / 0004 / 0041** 系列，
  并逐项标注本项目「已实现 / 未实现 / 不可用」。
- `docs/03-安全设计专章.md:40-51`（§1.2 合规基线）：
  **GB/T 22239-2019（等保 2.0）三级**、**GM/T 0054-2018**、
  **GB/T 35273-2020**、《个人信息保护法》《数据安全法》、
  OWASP ASVS 4.0 / API Security Top 10；`:790-805`（§8.2）做等保条款映射。

如实边界：
- `docs/03:52` 自述「本章不构成法律意见，也不替代专业等保测评与密评」。
- `docs/08-SM4方案变更说明.md` 说明 01–07 中的「SM4-GCM」是**目标表述**，
  真实落地为 SM4-CBC/CTR + HMAC-SM3（EtM）；`docs/13:25-29` 指出 GCM 属 NIST 模式、
  并非国密标准，当前 EtM 方案在合规性与可行性上更贴合。

#### 3.1.2 国产化替代方案是否较原先方案有优势，安全性是否符合国家要求

**判定：🟡 技术对齐有论证、有优势；合规资质明确未达标，不能宣称「符合国家要求」。**

优势证据（相对通用 Web 栈 / 公有云方案）：
- 全栈国产化组合：**仓颉（Cangjie）+ openGauss + 鸿蒙 NEXT 客户端**，
  国密 SM3 / SM4 / HMAC-SM3 自研组合（`docs/13:33-44`，与 OpenSSL 3.5.7 逐字节对齐）。
- **纯仓颉进程内媒体引擎**（`README.md:88`）：PNG / BMP / JPEG / PDF / OCR / 缩略图 /
  像素水印全在 `ams-server` 内完成，运行时不依赖系统字体、GDI、Python 或外部进程；
  字模由构建期生成器产出，隐私数据不出进程。
- **本地优先、数据自持、失败关闭**（`README.md:38`）：敏感字段字段级 SM4 加密 + 盲索引，
  密钥不经服务端明文落库；密码学原语缺失时按失败关闭而非降级（`docs/13:72`）。

硬边界（必须如实陈述）：
- **未取得商用密码产品认证**：`SECURITY.md:39`、`deploy/RUNBOOK.md:406`、
  `docs/13:60,66-71` 一致写明「**未做商用密码产品认证 / 密评 / 等保测评**」，
  并明确「代码层面对齐国密算法 ≠ 取得认证」；进入信创采购目录须另行送检。
- **SM2 未实现**（SDK 未提供，`docs/13:22,58`），导出包签名改用 **HMAC-SM3（对称）**，
  不是公钥签名，不支持第三方公钥验签。
- `docs/13:86-97`（§5.2 待推进）：**ARM64（鲲鹏 / 飞腾）编译运行验证**、
  **麒麟 / 统信 UOS 运行时依赖验证**、国密 CA / SM2 TLS、商密产品认证，均为待办。
- 底层 stdx 是否通过国密合规性测试需向 SDK 提供方索取声明，本仓不背书（`docs/13:69`）。

> **一句话**：「技术对齐国密」成立，「符合国家认证要求」**不成立**；两者不可混写。

#### 3.2.1 运行环境是单一类型设备部署，还是跨端部署

#### 3.2.2 项目是使用 Web 还是独立客户端

**判定：✅ 两者都有（Web 为主，鸿蒙原生客户端为扩展）。**

#### 3.2.3 项目的部署方式是二进制部署还是容器部署

**判定：✅ 双形态均可用；二进制形态的图形化启动器已于 2026-11-13 补齐（方案 A）。**

证据（双形态）：
- 二进制：`scripts/package.sh` 产出 `bin/ams-server.exe` + 运行时 DLL + `web/` +
  `config/` + `scripts/` + **launcher/** + LICENSE；`docs/09:8-32` 方式 A，
  `README.md:256-278` 与 `deploy/README.md:55-57` 描述单机部署。
- 容器：`deploy/docker/Dockerfile.prebuilt` + `deploy/compose/docker-compose.yml`，
  `docs/09` 方式 B 与 `docs/02` §7/§8 双形态矩阵；
  v1.3.0 Release 资产 `ams-release-1.3.0-windows-x86_64.zip` 已实证分发。

**曾经的缺口（评估时提出，现已补齐）**：`scripts/package.sh:278-311` 生成的 `start.cmd`
是纯命令行批处理，须手工填 `config/application.env`、命令行执行、再自行开浏览器；
当时全仓 `launcher` / `托盘` / `GUI` 等 0 命中，没有桌面外壳，对
「个人 / 家庭私有化部署、非技术用户」定位（`docs/01:63-72`）构成上手门槛。

**补齐实现（方案 A，双平台）**：

| 平台 | 文件 | 形态 | 依赖 |
| --- | --- | --- | --- |
| Windows | `scripts/launcher/AMS-Launcher.ps1` + `.cmd` | PowerShell 5.1 + WinForms（托盘 + 向导 + 日志窗） | 仅系统自带组件，**不写 C#、不编译、不分发任何 .NET/JVM 二进制** |
| Linux / macOS | `scripts/launcher/AMS-Launcher.sh` + `.desktop` | Bash 交互向导；有桌面且装 zenity 时弹图形菜单，headless 自动退化文本菜单 | bash / coreutils / curl / openssl(可选)，零新增运行时 |

- 随包分发：`scripts/package.sh` 新增 `[5.5/6]` 平台分支，插入点在 `[6/6] 校验和`
  **之前**，故 `CHECKSUMS.sha256` 与 zip 自动覆盖新文件（无需改校验逻辑）。
  Windows 包携带 `.ps1`/`.cmd`，Linux 包携带 `.sh`/`.desktop`（含可执行位）。
- 失败关闭契约（七条红线，实现与校验一一对应）：**不生成/兜底密钥**（生成按钮必须
  显式点击 + 显式确认落盘 + 备份提示）、预检失败就不调用 `Process.Start`、不吞退出码、
  **不自动重启**、`/api/health` 只作 liveness、日志按密钥键名脱敏、
  不写 `deployment.env` / 不碰 `/setup`。启动器只调用 `start.cmd` / `start.sh`，
  **服务端 `main.cj:120-139` 的 SEC-001 仍是唯一权威**。
- 静态防线：`scripts/ci/verify-package.sh` 断言 launcher 文件齐全、不含硬编码凭据
  默认值、不含自动重启模式；负向测试（注入假密钥）已验证会被拦下并 `exit 1`。

如实边界：
- 启动器是**可选的桌面外壳，不替代命令行入口**；`start.cmd` / `start.sh` 仍是权威。
- **生产容器形态仍刻意无图形化管理界面**（compose + 健康检查为命令行），这是设计选择而非缺口；启动器本身支持在「提供显示的容器」里跑 GUI（见下「容器形态 GUI」）。
- **真实 GUI 交互实测已完成（2026-11-13，Windows 桌面会话 SessionId=1 / 1920×1080）**：
  用真实 `PowerShell 5.1 -STA` 会话渲染主窗口与配置向导并截屏核对 —— 中文无乱码、
  六个按钮与九个输入项无重叠截断、两个「生成」按钮位于 TOKEN_SECRET / KEK 行、
  三个密钥框掩码生效、托盘图标可见；点击「启动」在凭据缺失时进入
  `PreflightFailed` 且**服务进程数 0、`$Script:Proc` 为 null**；补齐三项凭据后

### 4.2 相比较市场上现存的方案，有什么优势是现存方案没有的

**判定：🟡 可提炼五条可查证的组合优势，但原先无独立文档、无量化对比。**

1. **字段级国密 + 盲索引**：敏感字段 SM4 加密，证件号走盲索引（可等值查询、
   服务端不可逆推），密钥不经服务端明文落库 —— `README.md:35`、`docs/03`。
2. **最小暴露的共享模型**：条目级共享链接（不可预测 token、可选访问密码、失败上限、
   有效期、高敏条目连签发机关都不给）+ 家庭组三级授权（默认只读）；
   成员角色与全局 RBAC 完全隔离 —— `README.md:107-115`、`docs/12`。
3. **可举证的审计链 + 可携带导出包**：每条审计含前序哈希可校验链完整性，
   审计本身也被审计；导出包 HMAC-SM3 验签、离开原系统仍可验证 —— `README.md:112-115`。
4. **纯仓颉、零外部依赖的媒体链路**：PNG / BMP / JPEG 解码、PDF 抽文本与图像流、
   三路 OCR、缩略图、像素水印全在 `ams-server` 进程内；构建期生成字模，
   运行时不读系统字体 / 不起外部进程 / 不需 Python —— `README.md:88`、`docs/README.md:49-51`。
5. **失败关闭 + 存储可插拔 + 存量保护**：密码学原语缺失即抛错不降级；
   8 个存储平台可切换，库内已有附件时改 provider / endpoint / bucket 一律 Conflict 拒绝，
   防旧 `storage_key` 静默失效 —— `README.md:38`、`docs/16`、`docs/README.md` §六 Q2。

如实边界：
- 无第三方基准测试、无具名竞品的量化对比；上述为**能力组合的独特性**，
  不等同于市场结论。
- 每条优势都附带已知边界：`SECURITY.md`（水印不阻止翻拍、OCR 字典仅 220 字、
  短信异步投递不可同步感知）、`docs/13`（SM2 未实现、未认证）。
